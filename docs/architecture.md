# Architecture

## Boundaries

```text
SwiftUI views
    -> AppState (recording workflow, settings, synchronization)
        -> AppKit / AVFoundation (shortcuts, audio, focus, insertion)
        -> LocalStore / KeychainStore (local persistence)
        -> VoiceDraftCore
            -> SpeechClient / QwenRequests -> HTTPTransport / WebSocket session -> user's Bailian endpoint
            -> SyncCrypto -> SyncClient -> encrypted configuration server
```

Views submit changes through AppState; they do not write storage. The model adapter owns provider protocol details; the coordinator owns capture, cancellation, output delivery, and history. The server stores opaque encrypted configuration and does not proxy inference, receive audio, or manage model billing.

## Desktop navigation and editing

The main shell has Home, History, and Dictionary navigation. Home embeds the existing Studio recording and text-testing workspace, including all five modes, microphone selection, selection input, transcript processing, editable output, copying, and Accessibility controls. Shortcut hints show the actual Control-Option bindings; the UI does not register new shortcuts.

Settings is an in-window modal with its own navigation for general settings, Personalization, Models, Sync, About, and Help. The sidebar and Command-comma open the same modal. While it is open, the underlying page is disabled and `AppState.page` is `Settings`, preserving the existing pause on periodic configuration sync while forms are edited. Closing (including Escape) restores the previous page. Models and Sync retain their existing editors and coordinator calls.

Dictionary searches terms and aliases and filters enabled/disabled entries; automatic term discovery is not implemented. Add/edit, bulk add, enable, and delete actions update a fresh copy of shared settings through `AppState.save`. Entries retain their stable IDs and all rich vocabulary fields. Successful edits save immediately; validation/persistence errors keep the editor open. Writing style and translation target have an explicit Save action in Personalization.

History groups saved entries by local calendar date, supports text search and dictation/question filters, and retains original-transcript details, copy, single-entry deletion, clear-all confirmation, and future-history opt-out. The existing 500-entry limit is unchanged. Home counts are derived from retained local history and the active dictionary, not lifetime usage or estimates of time saved. No history cloud-sync or provider zero-retention claim is made.

Page copy uses the `Desktop.strings` table in the same eight language bundles as existing controls. `VOICEDRAFT_PREVIEW=1` opens an isolated interactive preview; `VOICEDRAFT_CAPTURE_PREVIEWS=<directory>` renders all six main destinations and exits. Both skip persisted configuration, Keychain reads, and global shortcut registration. `VOICEDRAFT_PREVIEW_FIXTURES=1` adds synthetic dictionary/history data only inside preview mode. Preview edits remain in memory; do not use provider, credential, or permission actions during visual checks.

## Models and inference

`ModelProfile` has a stable UUID, role, name, full endpoint, model ID, explicit adapter and additional JSON parameters. `ModelCatalog` lists only supported ASR models; each entry specifies its adapter and vocabulary capability. Text models use the chat adapter with a model picker and a custom Qwen text deployment option. A saved profile's UUID also identifies its local Keychain credential. Speech and writing profiles can have different accounts, endpoints, regions, and models. Additional JSON cannot override messages, model, streaming mode, or authentication.

Speech adapters are separate: Qwen3-ASR-Flash uses compatible HTTP chat audio and unweighted vocabulary context; Qwen-Audio-3.0/3.1-ASR-Flash uses native HTTP `input`/`parameters` and `output.text`; Qwen-Audio-3.1-ASR-Flash-Message uses task-based WebSocket inference. All models consume the same `SharedSettings.vocabulary`; profiles never own terms, weights, or vocabulary enablement. `VocabularyEntry` stores a stable ID, term, enabled flag, normalized strength (0–100), priority, language code, preferred output spelling, spoken aliases, and optional IPA pronunciation. This is the provider-independent source; adapters project a supported subset without mutating it. The first release still implements only the listed Qwen protocols, not additional providers or pronunciation training services.

`VocabularyProjection` is shared by request builders and the read-only model preview. Weighted Qwen adapters map strength to 1–5; the first 50 enabled priority terms use 50 and subsequent priority terms use 5. They send at most 2,000 distinct terms, enforce the provider's 15-character non-ASCII / seven-word ASCII limits, and omit whole unsupported terms. Context ASR uses a client budget of 300 terms and 6,000 UTF-8 bytes without weights. Both prioritize priority terms, then strength, then saved order; duplicate text uses the strongest eligible occurrence. Current ASR adapters retain language/alias/output/pronunciation metadata locally but do not send unsupported fields. The UI reports omitted terms and downgraded priority. Writing uses enabled terms, spelling, and aliases as structured guidance, never automatic replacements. Global vocabulary disablement affects both recognition and writing.

App storage allows longer terms than a provider (up to 30,000 characters per field, 50 aliases per entry, 200,000 entries), so old plain-text vocabulary and unsupported phrases survive migration. Sync rejects plaintext larger than 700,000 bytes before uploading, within the existing envelope/server limit. Additional speech JSON cannot bypass the global source through `vocabulary` or `vocabulary_id`; old remote resource references are retained for recovery, but require importing their contents into the app vocabulary.

Capture binds an explicitly selected `AVCaptureDeviceInput` for each take, limited to four minutes. Selection is a local device UID; nil resolves the system default at start, while an unavailable explicit device fails without fallback. The actual device name and elapsed time appear in the compact HUD tooltip. This never changes macOS Sound settings. Session errors/disconnects fail the take; per-run identities prevent stale callbacks from changing another run.

HTTP adapters retain the recorded-file path: `AVCaptureAudioFileOutput` produces mono 16 kHz 16-bit PCM WAV, with startup/finalization deadlines, user-only file permissions, and format validation before reading and uploading after stop. The recorded-WAV Message session remains available to core callers and tests.

The Message adapter's microphone path is live. After `run-task` and `task-started`, a separate `LiveAudioRecorder` starts `AVCaptureAudioDataOutput`, configured to convert to mono 16 kHz signed 16-bit little-endian PCM. `PCM16Audio` validates the delivered sample format and byte count before upload; no raw live recording file is created. Capture runs on its own serial queue. A bounded `LiveAudioFeed` assembles 3,200-byte (100 ms) frames with at most five seconds buffered; overflow fails explicitly, rather than omitting speech. Stop drains queued capture callbacks, flushes the final partial frame, closes the feed, and sends `finish-task` only after all audio sends complete.

`MessageASRSession.transcribeLive` concurrently uploads PCM and receives events. `intermediate_result_enabled` is enabled; hypotheses replace previous text by sentence ID, finalized sentences supersede hypotheses, and heartbeats are ignored. Only finalized nonempty text after `task-finished` can reach writing/insertion. An unexpected task ID, unfinished nonempty hypothesis, premature task completion, capture failure, or interrupted upload cannot return partial success. Handshake/finalization/whole-session deadlines are 15/30/300 seconds. Cancellation and all exits close the socket and unblock sends/receives; app generation checks also reject late UI updates. There is no automatic network reconnection or audio retry. Native URLSession supplies TLS and rejects redirects. Tests inject an in-memory socket; provider availability, hardware capture and latency still require real-account validation.

Live ASR disables `disfluency_removal_enabled` even when configured in advanced JSON, preserving spoken corrections for the writing stage. Polish and Translate instruct the writer to apply unambiguous later corrections and remove those correction instructions, without executing external actions. Verbatim remains literal. The live preview is provisional and never gets inserted on its own. Protocol references: Alibaba's [client events](https://help.aliyun.com/zh/model-studio/qwen-asr-message-client-events) and [server events](https://help.aliyun.com/zh/model-studio/qwen-asr-message-server-events).

Before opening the microphone, the coordinator validates the selected adapter/model/endpoint and vocabulary. Unknown legacy ASR IDs remain available for editing but cannot fall back to chat HTTP. Provider failures expose the HTTP status, recognized diagnostic codes, and UUID request/task IDs; arbitrary error messages are omitted because providers can echo audio, prompts, or credentials.

Writing mode determines the system instruction; transcript and selected text are structured data in the user message. Qwen may still make semantic mistakes; outputs are editable and the original transcript remains accessible.

HTTP recordings are written to a randomly named file with user-only permissions, read at stop, then deleted even if a later model request fails. No audio is stored by the sync server. Provider-side handling follows the user's Bailian account and endpoint policies; client-side deletion is not a claim about provider retention. A forced process termination can leave a temporary recording; startup cleanup is tracked in the roadmap.

An active run captures its selected models, credentials, vocabulary, mode, selection, and input target before recording. Configuration changes do not alter a running request. Cancel invalidates the run ID and cancels the task; late responses cannot insert text. When writing fails after ASR succeeds, the raw transcript is preserved and no partial rewrite is automatically inserted.

## System integration

SwiftUI owns the application menu through scene commands; AppKit owns the main window and recording panel. Standard editing shortcuts (undo, redo, cut, copy, paste, and select all) dispatch through AppKit's responder chain to the focused editor, including model configuration sheets. Do not assign `NSApp.mainMenu` during launch: SwiftUI can replace it when assembling its scene menus.

All single-line inputs, including custom model IDs and global vocabulary fields, use `SingleLineField`, an AppKit `NSTextField`/`NSSecureTextField` bridge with `usesSingleLineMode` enabled. The native field editor replaces pasted line/paragraph separators with spaces and suppresses newline insertion commands; text scrolls horizontally. A one-line height or SwiftUI `lineLimit` alone is not an input constraint. Keep the native editing path for undo, selection, and input methods; multiline transcript, selection, vocabulary, style, and JSON editors remain `TextEditor` views.

On explicit saves, profile names/endpoints/model IDs, translation targets, API keys, and sync URL/token values are trimmed at their edges. Model requests also trim the model ID and reject a whitespace-only ID, including for older stored configurations and unsaved connection tests. Model editors trim existing profile values on opening; search ignores outer query whitespace. Sync passphrases retain their exact spaces, since those spaces affect encryption. Existing credentials are not rewritten merely by opening a page. Model editors check Keychain metadata and display a fixed masked placeholder plus a saved-key label. The placeholder is never credential data. An empty replacement preserves the stored key; removing it requires the explicit Remove saved key action followed by Save. Cancelling leaves Keychain unchanged.

Carbon global hotkeys start/stop workflows. A nonactivating AppKit panel that cannot become key or main displays a compact Cancel/waveform/Finish capsule without stealing focus. With live text it expands upward into a scrollable preview; after a result requiring manual copying it shows a persistent, scrollable copy card. The card closes immediately after a successful Copy, on dismissal, or when replaced by another take; automatic insertion shows brief success feedback. A failed clipboard write keeps the card and its text available. Accessibility captures the frontmost application's focused element and selected range/text. A destination must expose a writable selected-text attribute, or a text input role with a writable value or selection range. A writable selection range also qualifies a web editor for Command-V even when its text attributes are read-only; disabled/non-input elements are not paste targets. Before insertion, the app rechecks editability, process, field, selection, and range. No input focus, disabled automatic insertion, Ask mode, or failed focus validation routes the completed result to the copy card. Password fields are excluded. Missing Accessibility authorization and insertion errors are shown on the copy card instead of silently looking like absent input focus. Home also surfaces missing Accessibility authorization; a rebuilt ad-hoc signed app may need to be reauthorized by the user.

Insertion temporarily supplies the clipboard and sends Command-V with a private event source. It does not write AXSelectedText: Chromium can acknowledge that setter while its web accessibility action dispatcher ignores the requested replacement. An acknowledged AX write or a posted keyboard event is not insertion confirmation. The app polls the original field for up to 1.5 seconds, comparing its value with the expected UTF-16 selection replacement; editors omitting AXValue can confirm with the exact changed caret offset. Identical replacements require the expected selection collapse. Only confirmed updates report Text inserted. Unconfirmed results stay available on the copy card with an instruction to check the field first; there is no automatic retry that could duplicate text. Existing clipboard formats are restored on confirmation or timeout only if no newer clipboard change occurred. Once paste is queued, cancellation does not remove the temporary clipboard before this bounded observation finishes. The app never sends Enter or runs a model-generated command. Selected-text access and insertion require real-app compatibility testing.

## Persistence

`~/Library/Application Support/VoiceDraft/` contains versioned settings, per-device preferences, and up to 500 history records in user-readable JSON with mode 0600. The directory uses mode 0700. This is local storage, not an encrypted history database. Keys and the synchronization access token/passphrase use Keychain items accessible only on the device while unlocked.

History, recordings, microphone settings, paste preferences, and server login details are not part of the shared configuration. Disabling history affects future entries; deletion removes existing entries separately. Before an explicit remote replacement, the previous nonsecret settings are copied to `settings-before-sync.json`. This backup excludes keys; it is not a full encrypted vault backup.

## Settings schema v3

Schema v3 stores one rich app vocabulary and removes per-profile speech vocabulary settings. v1 protocol migration still infers only exact catalog IDs and repairs known paths on the existing origin; custom paths and unknown IDs stay editable. v1/v2 vocabulary migration starts with global lines, merges terms from all speech profiles, and lets the active profile win conflicting overrides. Its default weight maps to the global strength scale, its vocabulary switch becomes the app switch, and disabled inactive-profile terms remain disabled. Stable IDs derive from namespaced term hashes so decoding the same legacy snapshot twice preserves equality for sync conflict detection. Legacy tab separators normalize to spaces; long valid legacy terms are retained. Profile UUIDs, key associations, and unrelated model parameters remain intact. Migration does not access credentials or persist automatically; the next explicit save writes v3. Older clients reject v3, so update every syncing client before sharing it. The encryption envelope and opaque server protocol are unchanged.

## Interface localization

Eight resource catalogs cover Simplified Chinese, Traditional Chinese, English, Japanese, Korean, German, French, and Spanish. `LocalizedMessage` separates stable source keys from interpolated user values; `L10n` resolves an explicit choice or the ordered system languages, with English fallback. Language is a local UserDefaults preference, separate from the translation target and encrypted shared settings. Switching it refreshes view labels, existing status messages, menu commands and menu-bar entries without rebuilding editor state. Cocoa-owned dialogs use the app-only `AppleLanguages` preference on the next launch; main-bundle `InfoPlist.strings` localizes the microphone usage description. User text, history contents, names, model IDs, parameters, and model prompts are never translated when changing the interface.

SwiftPM bundles must be copied into `Contents/Resources`; packaged builds explicitly resolve that copy and do not silently depend on the development build directory. Chinese lproj names are matched case-insensitively because SwiftPM lowercases them. `scripts/check-localizations.py` checks all catalog keys, argument placeholders, microphone descriptions and source literal coverage; Swift tests verify language matching and actual translated lookup for all eight languages.

## Encrypted sync protocol v1

Plaintext snapshot: `{settings: SharedSettings, credentials: {profileUUID: apiKey}}`.

1. The client validates the snapshot and derives a 256-bit key from the passphrase using PBKDF2-HMAC-SHA256, 600,000 iterations, and a fresh random 16-byte salt for each upload.
2. AES-256-GCM encrypts the UTF-8 JSON with a fresh nonce. Authenticated associated data is the UTF-8 string `VoiceDraft.sync.v1`.
3. The envelope has exactly `version: 1`, `algorithm: "PBKDF2-SHA256+AES-256-GCM"`, `iterations: 600000`, `salt` (base64), and `ciphertext` (base64 of CryptoKit's combined `nonce || ciphertext || tag`). This format is implementable on other platforms.
4. The service authenticates a separate bearer access token. The passphrase never leaves the client. Knowledge of the access token permits reading/replacing ciphertext but does not decrypt it.
5. `GET /v1/sync` returns `{revision, payload}`. Empty vaults return revision 0 and null payload. `PUT /v1/sync` requires the last known revision and the encrypted envelope; a SQLite transaction increments the revision atomically or returns HTTP 409.
6. The client decrypts and validates a remote snapshot before applying it. It refuses automatic overwrite when both local and remote settings changed. A remote copy identical to local state can reconcile a previous upload whose response was lost.

Sync is whole-vault optimistic concurrency, not field-level merging. The initial service has one vault and access token per deployment. Devices use that shared token; user registration, individual device revocation, teams, and multiple tenant vaults are future work. Changing the passphrase alone cannot decrypt the existing vault: coordinated vault migration/rotation is not implemented.

HTTPS is mandatory except loopback development. HTTP redirects are rejected to avoid forwarding credentials. The client detects decreasing revisions relative to a previous successful sync; there is no server-independent freshness proof for a new device. The server can observe envelope size, revisions, and access timing. End-to-end encryption does not hide that metadata or stop a server administrator from deleting data.

## Extension path

Add catalog entries only alongside a protocol adapter, capability definitions, and request/response/cancellation fixtures. Do not assume a changed model ID makes ASR protocols compatible. Keep live microphone and recorded-file capture lifecycles separate when adding adapters, preserving current HTTP behavior. Future clients must reproduce encryption test vectors and sync revision behavior before being released.
