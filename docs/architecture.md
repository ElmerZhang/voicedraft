# Architecture

Current feature expansion and migration details: [selected-features.md](selected-features.md). The original sections below document the initial Qwen architecture; where they describe v4/four-minute/500-entry limits, the v5 rules in the expansion take precedence.

## Boundaries

```text
SwiftUI views
    -> AppState (recording workflow, settings, synchronization)
        -> AppKit / AVFoundation (shortcuts, audio, focus, insertion)
        -> LocalStore / KeychainStore (local persistence)
        -> VoiceDraftCore
            -> SpeechClient / WritingClient -> HTTPTransport / WebSocket session -> configured provider
            -> SyncCrypto -> SyncClient -> encrypted configuration server
```

Views submit changes through AppState; they do not write storage. The model adapter owns provider protocol details; the coordinator owns capture, cancellation, output delivery, and history. The server stores opaque encrypted configuration and does not proxy inference, receive audio, or manage model billing.

Completed recognition without text is represented by `SpeechRecognitionError.noSpeech`. AppState quietly releases capture/tasks/effects, closes the HUD and returns to ready without writing empty history or invoking the writing model. Silent chunks are skipped within longer Qwen recordings; only an entirely empty combined transcript is no-speech. Malformed responses, transport failures, incomplete hypotheses and empty writing output remain failures.

Onboarding has four steps: optional field selection/starter vocabulary, models, permissions, and shortcut guidance. It keeps its heading and navigation outside a scrollable step body and reuses model controls without the full Models page heading. While mounted, its cancellable task refreshes microphone and Accessibility status every 500 ms, including while System Settings is frontmost. `VOICEDRAFT_CAPTURE_ONBOARDING=<directory>` renders all four steps with isolated preview data, AI/software selections and synthetic granted permissions, then exits; this does not test a real OS permission change.

`DomainVocabularySelection` owns the curated AI, software, product/design, data, hardware, and education/research packs. Domains are multi-select and optional; each term can be unchecked. Explicit exclusions survive domain deselection/reselection within the sheet. Continue adds only reviewed terms as ordinary enabled manual entries (strength 50, no priority) through AppState's existing save/sync flow. Existing terms, aliases and preferred spellings, including disabled entries, are matched case/width-insensitively and never overwritten or re-enabled. Global vocabulary/learning preferences remain unchanged. No profession profile or schema change is needed; selection drafts are local to the sheet. Set up later does not import a draft. Existing users can reopen the guide from Settings. The catalog deliberately avoids generic PR/UI/API/AI/README entries. Canonical naming references include [FigJam](https://www.figma.com/figjam/), [LangChain](https://reference.langchain.com/) and [Raspberry Pi](https://www.raspberrypi.com/products/raspberry-pi-pico/); bundled packs are editable vocabulary suggestions, not an accuracy guarantee.

The sync server is a separate Go module in `server/`: `cmd/voicedraft-sync` owns environment configuration and graceful process shutdown; `internal/syncserver` owns HTTP validation/authentication and SQLite transactions. It uses Go's `net/http` and `database/sql` with a pinned [pure-Go SQLite driver](https://pkg.go.dev/modernc.org/sqlite), producing a binary with `CGO_ENABLED=0`. There is no Python server runtime. HTTP protocol v1, envelope fields, environment variables, and the existing `vault` table are unchanged. An immediate SQLite transaction protects revision comparison and replacement across independent connections/processes. See [server.md](server.md) for in-place migration and deployment.

Synthetic provider endpoints live in `internal/testfixture`, linked only by `cmd/integration-test`; the production command does not expose or include them. Go service tests use `httptest.ResponseRecorder` and actual temporary SQLite databases, so validation/storage coverage does not require listening on a port. The separate integration command starts a loopback server for the existing Swift client tests.

## Desktop navigation and editing

The main shell has Home, History, and Vocabulary navigation. Home embeds the existing Studio recording and text-testing workspace, including all five modes, microphone selection, selection input, transcript processing, editable output, copying, and Accessibility controls. Shortcut hints show the saved bindings. Carbon receives press/release events; an explicitly configured Fn key uses an Accessibility event tap. The pure RecordingGesture state machine distinguishes hold-to-talk from tap-to-lock, including microphone startup.

Settings is an in-window modal with its own navigation for general settings, Personalization, Models, Sync, About, and Help. The sidebar and Command-comma open the same modal. While it is open, the underlying page is disabled and `AppState.page` is `Settings`, preserving the existing pause on periodic configuration sync while forms are edited. Closing (including Escape) restores the previous page. Models and Sync retain their existing editors and coordinator calls.

Vocabulary searches terms and aliases, filters All / Auto-added / Manually-added, and has an independent enabled/disabled filter. Automatic terms use a teal sparkle; manual terms use a leaf. Add/edit, bulk add, enable, and delete actions update a fresh copy of shared settings through `AppState.save`. Entries retain their stable IDs, origin, and all rich vocabulary fields. Successful edits save immediately; validation/persistence errors keep the editor open. Writing style and translation target have an explicit Save action in Personalization.

### Agent context vocabulary discovery

Vocabulary's context action launches a cancellable utility task through AppState. It discovers `~/.codex/AGENTS.md`, `history.jsonl`, `sessions/`, `archived_sessions/`, and Markdown under `memories/`; for Claude it reads `~/.claude/CLAUDE.md`, `history.jsonl`, project session JSONL and project `memory/` Markdown. It then checks exact `AGENTS.md`, `CLAUDE.md` and `.claude/CLAUDE.md` files in up to 12 project directories referenced by session metadata/history. It never traverses other workspace contents or parent directories. Symlinks, subagent directories, skills, hidden descendants and unrelated files such as authentication/configuration are excluded.

Referenced existing project directories also contribute their basename, including lowercase/hyphenated names, and literal names from the exact allowlist `package.json` (`name`, dropping an npm scope), `Package.swift` (`Package(name:)`), `Cargo.toml` (`[package].name`), `pyproject.toml` (`[project].name`) and `go.mod` (module basename, dropping a version suffix). Manifests are read as data, never executed; each must fit within 32 KB and the project's shared 128 KB budget. Missing, unsupported/dynamic or malformed declarations produce no name. Home directories, symlinks, generic scaffold names and invalid name shapes are skipped. There is no repository or parent traversal. Project names are deduplicated with other terms, retain both agent sources when available, and take precedence before the 200-candidate cap. A `kind: project` label gives the model supporting evidence without sending the path or manifest. The prompt still filters generic labels; review rows show `Project · Codex / Claude` as applicable.

Discovery is on demand and local. Per agent, traversal stops at 12,000 entries and depth 5; reads prioritize global context, up to 12 recent memory files, then recent conversations, with at most 80 files / 8 MB. Individual reads are at most 512 KB; oversized JSONL preserves complete header and tail lines to retain metadata and recent messages. Referenced projects have an additional 128 KB read budget each. Limits and unreadable files are reported quietly in the candidate sheet. Missing agent directories are normal.

Conversation parsing understands Codex and Claude history/session formats, deduplicates user messages within each file, and excludes assistant/tool output, tool-result wrappers, sidechains, known injected environment/instruction messages and Codex subagent sessions. Credential/URL lines are filtered before deterministic name extraction; this is a heuristic, so the user reviews candidates. Local extraction proposes at most 200 case/width-deduplicated new terms with Codex/Claude source labels, excluding current terms, aliases and preferred spellings. The selected writing model receives only candidate IDs, words and term/project labels, with no raw conversations, file paths or manifest content. Its classification prompt excludes common abbreviations, ordinary technology words, generic file labels and incidental code symbols while keeping distinctive names and specialized terms useful to speech recognition. A strict JSON parser accepts at most 40 unique, in-range IDs, preserving the original spelling/source and the model’s usefulness order. Empty selections are valid; invented IDs, malformed output or transport errors do not silently expose the unfiltered list. The sheet offers retry or an explicit unfiltered review after failure. The bounded request uses the selected Chat Completions, Anthropic or Responses protocol, a 45-second timeout and 64 KB response limit. This is one additional model request per nonempty extraction attempt. Only user-selected terms enter shared vocabulary through the existing save/sync flow. Dismissing the sheet cancels its worker and cannot import terms or publish stale results. Isolated UI preview mode never scans the real home directory.

### Automatic vocabulary learning

Two independent, enabled-by-default switches control learning from corrections and discovering terms in dictation. Both also respect global vocabulary disablement. Polish and Verbatim results (including Home text tests) can feed learning after output delivery. Translate, Edit and Ask do not teach terms from translations or model answers. This is a separate, cancellable request to the selected Qwen writing model, with a 20-second timeout; it never delays insertion or changes the delivered text. It may incur an additional inference request per completed dictation or settled correction. Failure is shown quietly in Vocabulary/Home and cannot fail the dictation.

The learning prompt classifies distinctive names, products, projects and specialist terms. A strict JSON parser allows at most five corrections and five discoveries, bounded response/input sizes, short terms and exact source-text evidence. Explicit spoken recognition/spelling corrections and small user edits can add terms immediately; semantic rewrites, stutters, generic words, numbers, URLs and credentials are excluded by the prompt (structural guards also reject bare numbers, URLs and unsupported punctuation). Classification is still model-dependent, not a guarantee against incorrect terms. No global text replacement is performed, and mistaken spellings are not automatically stored as aliases.

New discoveries must occur in both raw and final text and be proposed in two distinct takes during the current app session. Repeated mentions or processing the same take twice cannot promote a term. Up to 1,000 unconfirmed spellings are held only in memory; they reset at restart, learning/model configuration changes, or remote configuration replacement. Existing enabled/disabled/manual entries and their aliases/preferred spellings are deduplicated case/width-insensitively and never overwritten. Deletion records a normalized SHA-256 spelling key to suppress later relearning, including in-flight responses; manually adding a word remains possible. The suppression hashes are not a secrecy mechanism for low-entropy terms.

For external input, an optional observer starts only after paste is posted. It must observe the expected inserted value, and then watches the same focused process/window/editor for a 45-second monotonic window. Fresh observation objects use 100 ms per-message AX timeouts without changing insertion objects or the process-wide timeout. It stops on cancellation, a new take, focus change, unreadable/secure/terminal input, an empty field, edits outside the insertion anchors, or a selection outside the dictated span. After a two-second stable edit, only the before/after dictated segment is sent for classification. Surrounding document text is used in memory to validate prefix/suffix anchors, never uploaded or persisted by this feature. UTF-16 offsets must align to character boundaries. Home's editable result uses a separate two-second debounce. Editors without AXValue (including some rich editors) and Warp terminals cannot provide this correction feedback; their spoken corrections and ordinary dictation discovery still work. There are no keylogging hooks or focus reacquisition.

Automatic learning merges into current settings rather than the capture-time snapshot, validates and persists through AppState/LocalStore, marks configuration dirty for encrypted sync, and respects current switches and deletion suppression. Changed models, opt-outs and remote replacement invalidate in-flight requests. Only confirmed vocabulary entries/origins, switches and deletion hashes sync; raw correction observations and pending discoveries do not. Origins and learning controls require settings schema v4.

Automatically added terms stay enabled, as requested by the user, but remain weaker evidence than manual spellings. The request projection orders manual terms before automatic ones, so recognition/writing budgets and use frequency cannot crowd them out. Weighted Qwen hints cap automatic terms at 2 (including previously stored automatic priority terms); their stored strength/priority are preserved. Editing and saving a term explicitly confirms it as manual, restoring its configured strength and priority behavior. Exact automatic duplicates of an enabled manual term, preferred spelling or alias are excluded from requests without deleting stored entries. There is no per-brand rule, inferred alias, fuzzy replacement, or confirmation queue.

History groups saved entries by local calendar date, supports text search and dictation/question filters, and retains original-transcript details, copy, single-entry deletion, clear-all confirmation, and future-history opt-out. The existing 500-entry limit is unchanged. Home counts are derived from retained local history and the active vocabulary, not lifetime usage or estimates of time saved. No history cloud-sync or provider zero-retention claim is made.

Page copy uses the `Desktop.strings` table in the same eight language bundles as existing controls. `VOICEDRAFT_PREVIEW=1` opens an isolated interactive preview; `VOICEDRAFT_CAPTURE_PREVIEWS=<directory>` renders all six main destinations and exits. Both skip persisted configuration, Keychain reads, and global shortcut registration. `VOICEDRAFT_PREVIEW_FIXTURES=1` adds synthetic vocabulary/history data only inside preview mode. Preview edits remain in memory; do not use provider, credential, or permission actions during visual checks.

## Models and inference

`ModelProfile` has a stable UUID, role, name, full endpoint, model ID, explicit adapter and additional JSON parameters. `ModelCatalog` lists only supported ASR models; each entry specifies its adapter and vocabulary capability. Text models use the chat adapter with a model picker and a custom Qwen text deployment option. A saved profile's UUID also identifies its local Keychain credential. Speech and writing profiles can have different accounts, endpoints, regions, and models. Additional JSON cannot override messages, model, streaming mode, or authentication.

Speech adapters are separate: Qwen3-ASR-Flash uses compatible HTTP chat audio and unweighted vocabulary context; Qwen-Audio-3.0/3.1-ASR-Flash uses native HTTP `input`/`parameters` and `output.text`; Qwen-Audio-3.1-ASR-Flash-Message uses task-based WebSocket inference. All models consume the same `SharedSettings.vocabulary`; profiles never own terms, weights, or vocabulary enablement. `VocabularyEntry` stores a stable ID, term, enabled flag, normalized strength (0–100), priority, language code, preferred output spelling, spoken aliases, and optional IPA pronunciation. This is the provider-independent source; adapters project a supported subset without mutating it. The first release still implements only the listed Qwen protocols, not additional providers or pronunciation training services.

`VocabularyProjection` is shared by request builders and the read-only model preview. Weighted Qwen adapters map manual strength to 1–5; the first 50 enabled manual priority terms use 50 and subsequent priority terms use 5. Automatic terms are capped at 2. They send at most 2,000 distinct terms, enforce the provider's 15-character non-ASCII / seven-word ASCII limits, and omit whole unsupported terms. Context ASR uses a client budget of 300 terms and 6,000 UTF-8 bytes without weights. Both prioritize manual origin, then priority, strength, use count and saved order; duplicate text uses the strongest eligible occurrence within that order. Current ASR adapters retain language/alias/output/pronunciation metadata locally but do not send unsupported fields. The UI reports adapter omissions, superseded automatic terms and downgraded manual priority. Writing uses the same order for up to 300 enabled entries, spelling, aliases and origin as structured guidance. It explicitly prefers user-confirmed manual spellings for clear phonetic recognition errors and treats automatic spellings as low-confidence suggestions; uncertain matches and quoted spelling examples stay intact. There are no automatic string replacements. Global vocabulary disablement affects both recognition and writing.

Qwen Message ASR additionally receives whole manual terms as a `payload.input.context` user message with `input_text`, limited to 400 Unicode scalars including separators. Unsupported/oversized terms are skipped whole. Automatic terms remain in the weighted vocabulary but are not reinforced in this unweighted domain context. No history or extra user text is sent by this path. The request shape and limits follow the [Message client-event API](https://help.aliyun.com/zh/model-studio/qwen-asr-message-client-events). Other ASR adapters retain their documented request shapes.

App storage allows longer terms than a provider (up to 30,000 characters per field, 50 aliases per entry, 200,000 entries), so old plain-text vocabulary and unsupported phrases survive migration. Sync rejects plaintext larger than 700,000 bytes before uploading, within the existing envelope/server limit. Additional speech JSON cannot bypass the global source through `vocabulary` or `vocabulary_id`; old remote resource references are retained for recovery, but require importing their contents into the app vocabulary.

Capture binds an explicitly selected `AVCaptureDeviceInput` for each take, limited to four minutes. Selection is a local device UID; nil resolves the system default at start, while an unavailable explicit device fails without fallback. The actual device name and elapsed time appear in the compact HUD tooltip. This never changes macOS Sound settings. Session errors/disconnects fail the take; per-run identities prevent stale callbacks from changing another run.

HTTP adapters retain the recorded-file path: `AVCaptureAudioFileOutput` produces mono 16 kHz 16-bit PCM WAV, with startup/finalization deadlines, user-only file permissions, and format validation before reading and uploading after stop. The recorded-WAV Message session remains available to core callers and tests.

The Message adapter's microphone path is live. After `run-task` and `task-started`, a separate `LiveAudioRecorder` starts `AVCaptureAudioDataOutput`, configured to convert to mono 16 kHz signed 16-bit little-endian PCM. `PCM16Audio` validates the delivered sample format and byte count before upload; no raw live recording file is created. Capture runs on its own serial queue. A bounded `LiveAudioFeed` assembles 3,200-byte (100 ms) frames with at most five seconds buffered; overflow fails explicitly, rather than omitting speech. Stop drains queued capture callbacks, flushes the final partial frame, closes the feed, and sends `finish-task` only after all audio sends complete.

`MessageASRSession.transcribeLive` concurrently uploads PCM and receives events. `intermediate_result_enabled` is enabled; hypotheses replace previous text by sentence ID, finalized sentences supersede hypotheses, and heartbeats are ignored. Only finalized nonempty text after `task-finished` can reach writing/insertion. An unexpected task ID, unfinished nonempty hypothesis, premature task completion, capture failure, or interrupted upload cannot return partial success. Handshake/finalization/whole-session deadlines are 15/30/300 seconds. Cancellation and all exits close the socket and unblock sends/receives; app generation checks also reject late UI updates. There is no automatic network reconnection or audio retry. Native URLSession supplies TLS and rejects redirects. Tests inject an in-memory socket; provider availability, hardware capture and latency still require real-account validation.

Live ASR disables `disfluency_removal_enabled` even when configured in advanced JSON, preserving spoken corrections for the writing stage. Polish and Translate instruct the writer to apply unambiguous later corrections and remove those correction instructions, without executing external actions. Verbatim remains literal. The live preview is provisional and never gets inserted on its own. Protocol references: Alibaba's [client events](https://help.aliyun.com/zh/model-studio/qwen-asr-message-client-events) and [server events](https://help.aliyun.com/zh/model-studio/qwen-asr-message-server-events).

Before opening the microphone, the coordinator validates the selected adapter/model/endpoint and vocabulary. Unknown legacy ASR IDs remain available for editing but cannot fall back to chat HTTP. Provider failures expose the HTTP status, recognized diagnostic codes, and UUID request/task IDs; arbitrary error messages are omitted because providers can echo audio, prompts, or credentials.

Writing mode determines the system instruction; transcript and selected text are structured data in the user message. Qwen may still make semantic mistakes; outputs are editable and the original transcript remains accessible.

Polish and Translate share explicit dictation cleanup rules with source-language examples: remove clear stutters (including repeated characters inside a word), hesitation fillers, accidental duplicates, and abandoned phrase starts. Preserve natural reduplication, deliberate emphasis, quoted verbatim speech, negation, uncertainty, conditions, numbers, identifiers, and technical terms; ambiguous repetitions remain unchanged. Translation applies cleanup before translating into the configured target language. Tone preservation refers to intended wording, not speech disfluencies. Habitual discourse fillers such as “然后” are removed when they merely bridge thoughts, including sentence-initial use; actual event/step sequencing, logical meaning, verbatim quotations and ambiguous uses remain. Language preservation applies to retained content and does not override filler cleanup. Paired cleanup/retention examples guide this contextual decision; there is no word blacklist. No local repetition regex, extra inference pass, or model parameter override is used. The cleanup policy does not apply to Verbatim, Edit, or Ask. Request-contract tests verify mode scope and intact structured input; actual model compliance needs separate quality evaluation.

Polish separately requires language preservation at word/phrase/clause level, including ordinary words and conjunctions in mixed-language text, rather than merely retaining names or the majority language. Only minimal same-language cleanup/spelling/grammar changes are allowed; explicit self-corrections retain the dictated replacement wording. Style, application and recent-context hints cannot choose a different output language, and vocabulary is not a translation glossary for already-correct expressions. Mixed-language examples and a final comparison instruction reinforce this constraint. Translation workflow instructions are present only in Translate; Edit still follows explicit editing instructions. Raw structured input remains untouched across all writing protocols. These are model instructions, not a deterministic detector or a guarantee of compliance; no language-ratio heuristic or automatic replacement is applied to returned text.

HTTP recordings are written to a randomly named file with user-only permissions, read at stop, then deleted even if a later model request fails. No audio is stored by the sync server. Provider-side handling follows the user's Bailian account and endpoint policies; client-side deletion is not a claim about provider retention. A forced process termination can leave a temporary recording; startup cleanup is tracked in the roadmap.

An active run captures its selected models, credentials, vocabulary, mode, selection, and input target before recording. Configuration changes do not alter a running request. Cancel invalidates the run ID and cancels the task; late responses cannot insert text. When writing fails after ASR succeeds, the raw transcript is preserved and no partial rewrite is automatically inserted.

## System integration

WeChat 4.1.15 on the validated Mac exposes its main window and standard window controls but no chat input element. `KeyboardSurfacePolicy.acceptsOpaqueWeChat` allows keyboard paste only for `com.tencent.xinWeChat`, a nonmodal standard main window titled Weixin/WeChat/微信, no resolved editor, no unsafe focused role, and an available native Paste menu command. The normal AX editor path takes precedence whenever available. A bounded menu-only read identifies Command-V or Qt's `paste:` identifier; it does not search chat content. The existing process/window/element and selection checks still run before paste. Since opaque chat focus has no field identity, a per-take `OpaqueInputFocusGuard` invalidates on global clicks, ordinary key presses or any application activation during the take; configured recording shortcuts are excluded. It stores no typed characters/positions and unregisters after delivery, cancellation or failure. This compatibility path reports paste sent without claiming AX confirmation, does not observe correction text, and never sends Enter. It cannot prove the chat recipient or input caret from AX; application-internal changes with no observed input may remain invisible. Native automation also observed this limitation in [WeChat 4.1.x](https://github.com/huj28-creator/wechat-fastbridge/issues/1).

Fn's event tap consumes both press and release, but macOS's separate Globe action can still switch input sources or invoke emoji/Dictation. Fn users must set **System Settings → Keyboard → Press Fn (Globe) key to → Do Nothing** ([Apple keyboard settings](https://support.apple.com/en-gb/guide/mac-help/kbdm162/mac)). Home, shortcut preferences and the final onboarding step show `FnShortcutStatus` for enabled Fn bindings. The view reads `com.apple.HIToolbox/AppleFnUsageType` through `FnSystemAction`; only explicit zero is ready, with missing/unknown values requiring a settings check. A cancellable one-second refresh runs only while the view is mounted with an enabled Fn binding, including while System Settings is frontmost. Preview mode skips OS reads. The settings button opens the native Keyboard pane; VoiceDraft does not write the preference or claim it can restore its live behavior on quit. This system-wide choice persists outside VoiceDraft. Other shortcut events continue through the existing Carbon/event-tap paths.

SwiftUI owns the application menu through scene commands; AppKit owns the main window and recording panel. Standard editing shortcuts (undo, redo, cut, copy, paste, and select all) dispatch through AppKit's responder chain to the focused editor, including model configuration sheets. Do not assign `NSApp.mainMenu` during launch: SwiftUI can replace it when assembling its scene menus.

All single-line inputs, including custom model IDs and global vocabulary fields, use `SingleLineField`, an AppKit `NSTextField`/`NSSecureTextField` bridge with `usesSingleLineMode` enabled. The native field editor replaces pasted line/paragraph separators with spaces and suppresses newline insertion commands; text scrolls horizontally. A one-line height or SwiftUI `lineLimit` alone is not an input constraint. Keep the native editing path for undo, selection, and input methods; multiline transcript, selection, vocabulary, style, and JSON editors remain `TextEditor` views.

On explicit saves, profile names/endpoints/model IDs, translation targets, API keys, and sync URL/token values are trimmed at their edges. Model requests also trim the model ID and reject a whitespace-only ID, including for older stored configurations and unsaved connection tests. Model editors trim existing profile values on opening; search ignores outer query whitespace. Sync passphrases retain their exact spaces, since those spaces affect encryption. Existing credentials are not rewritten merely by opening a page. Model editors check Keychain metadata and display a fixed masked placeholder plus a saved-key label. The placeholder is never credential data. An empty replacement preserves the stored key; removing it requires the explicit Remove saved key action followed by Save. Cancelling leaves Keychain unchanged.

Carbon global hotkeys start/stop workflows. A nonactivating AppKit panel that cannot become key or main displays a compact Cancel/waveform/Finish capsule without stealing focus. With live text it expands upward into a scrollable preview; after a result requiring manual copying it shows a persistent, scrollable copy card. The card closes immediately after a successful Copy, on dismissal, or when replaced by another take; automatic insertion closes the panel as soon as Command-V has been queued. A failed clipboard write keeps the card and its text available. Accessibility captures the frontmost application's focused element and selected range/text. A text destination must expose a text input role with a writable selected-text, value, or selection-range attribute. A writable selection range also qualifies a web editor for Command-V even when its text attributes are read-only. Focused text/paragraph children resolve to the nearest input ancestor, with cycle/depth limits; unrelated editors, buttons and web-page containers are never searched. Disabled and password inputs stop ancestor traversal and remain excluded.

Before insertion, the app rechecks editability, process, window, canonical field, selection, and range. Empty editor values allow a missing caret to become the zero caret; unknown/nonempty values do not get this exception. Replacing an editor's focused paragraph does not change its destination, while moving to another field still does. Errors distinguish app/window/input/selection changes. No input focus, disabled automatic insertion, Ask mode, or failed focus validation routes the completed result to the copy card. Missing Accessibility authorization and insertion errors are shown on the copy card instead of silently looking like absent input focus. Home also surfaces missing Accessibility authorization; a rebuilt ad-hoc signed app may need to be reauthorized by the user.

Insertion temporarily supplies the clipboard and sends Command-V with a private event source. It does not write AXSelectedText: Chromium can acknowledge that setter while its web accessibility action dispatcher ignores the requested replacement. An acknowledged AX write or a posted keyboard event is not insertion confirmation. The app polls the original field for up to 1.5 seconds, comparing its value with the expected UTF-16 selection replacement; editors omitting AXValue can confirm with the exact changed caret offset. Identical replacements require the expected selection collapse. Only confirmed updates report Text inserted. A sent paste without an exact AX receipt is a separate outcome, not a thrown insertion failure: its already-hidden HUD stays hidden without a success checkmark or Copy prompt, and Home reports Paste sent · check the input field. This avoids offering a duplicate paste when a rich editor has accepted text without exposing a matching AX value/range. The result stays available in Home and, when enabled, History; there is no automatic retry. Missing input or pre-send failures still show the copy card. Existing clipboard formats are restored on confirmation or timeout only if no newer clipboard change occurred. Once paste is queued, cancellation does not remove the temporary clipboard before this bounded observation finishes. The app never sends Enter or runs a model-generated command. Selected-text access and insertion require real-app compatibility testing.

The insertion adapter calls `onPasteSent` synchronously after posting both paste events and before its first receipt-observation wait. AppState hides the current run's HUD in that callback. The 1.5-second clipboard/receipt window continues with the workflow busy, so another take cannot replace the temporary clipboard. There is no extra success-display delay after observation. Failures before posting do not call the callback and still present the copy card; cancellation and newer-run guards remain in place.

Warp (`dev.warp.Warp-Stable`) has a narrow keyboard-surface path for its standard, nonmodal window when focus exposes an enabled neutral container, a text area without a writable value, or no AX element. Exposed disabled/secure controls, buttons, normal form fields and dialogs do not use it. The same process, window and exposed surface must remain focused; only collapsed selection offsets may drift as terminal output advances. Terminal output is not treated as a replaceable editor value or insertion receipt. After one Command-V and the clipboard grace period, this path reports Paste sent to terminal rather than Text inserted. The result remains in Home and, when enabled, History. This is best-effort keyboard delivery: AX cannot establish pane identity when no focus element exists, or prove that a TTY application accepted/echoed the paste. Other apps retain editor confirmation. Real Warp/TUI compatibility and pane switching remain acceptance checks.

## Persistence

`~/Library/Application Support/VoiceDraft/` contains versioned settings, per-device preferences, and up to 500 history records in user-readable JSON with mode 0600. The directory uses mode 0700. This is local storage, not an encrypted history database. Keys and the synchronization access token/passphrase use Keychain items accessible only on the device while unlocked.

History, recordings, microphone settings, paste preferences, and server login details are not part of the shared configuration. Disabling history affects future entries; deletion removes existing entries separately. Before an explicit remote replacement, the previous nonsecret settings are copied to `settings-before-sync.json`. This backup excludes keys; it is not a full encrypted vault backup.

## Settings schema v4

Schema v4 adds vocabulary origins, learning switches and deleted-term suppression; v3 terms default to manual with IDs and metadata unchanged. v3 introduced one rich app vocabulary and removed per-profile speech vocabulary settings. v1 protocol migration still infers only exact catalog IDs and repairs known paths on the existing origin; custom paths and unknown IDs stay editable. v1/v2 vocabulary migration starts with global lines, merges terms from all speech profiles, and lets the active profile win conflicting overrides. Its default weight maps to the global strength scale, its vocabulary switch becomes the app switch, and disabled inactive-profile terms remain disabled. Stable IDs derive from namespaced term hashes so decoding the same legacy snapshot twice preserves equality for sync conflict detection. Legacy tab separators normalize to spaces; long valid legacy terms are retained. Profile UUIDs, key associations, and unrelated model parameters remain intact. Migration does not access credentials or persist automatically; the next settings save (including an automatically learned word) writes v4. Older clients reject v4, so update every syncing client before sharing it. The encryption envelope and opaque server protocol are unchanged.

## Interface localization

Eight resource catalogs cover Simplified Chinese, Traditional Chinese, English, Japanese, Korean, German, French, and Spanish. `LocalizedMessage` separates stable source keys from interpolated user values; `L10n` resolves an explicit choice or the ordered system languages, with English fallback. Language is a local UserDefaults preference, separate from the translation target and encrypted shared settings. Switching it refreshes view labels, existing status messages, menu commands and menu-bar entries without rebuilding editor state. Cocoa-owned dialogs use the app-only `AppleLanguages` preference on the next launch; main-bundle `InfoPlist.strings` localizes the microphone usage description. User text, history contents, names, model IDs, parameters, and model prompts are never translated when changing the interface.

SwiftPM bundles must be copied into `Contents/Resources`; packaged builds explicitly resolve that copy and do not silently depend on the development build directory. Chinese lproj names are matched case-insensitively because SwiftPM lowercases them. `scripts/check-localizations.py` checks all catalog keys, argument placeholders, microphone descriptions and source literal coverage; Swift tests verify language matching and actual translated lookup for all eight languages.

## Encrypted sync protocol v1

Plaintext snapshot: `{settings: SharedSettings, credentials: {profileUUID: apiKey}}`.

1. The client validates the snapshot and derives a 256-bit key from the passphrase using PBKDF2-HMAC-SHA256, 600,000 iterations, and a fresh random 16-byte salt for each upload.
2. AES-256-GCM encrypts the UTF-8 JSON with a fresh nonce. Authenticated associated data is the UTF-8 string `VoiceDraft.sync.v1`.
3. The envelope has exactly `version: 1`, `algorithm: "PBKDF2-SHA256+AES-256-GCM"`, `iterations: 600000`, `salt` (base64), and `ciphertext` (base64 of CryptoKit's combined `nonce || ciphertext || tag`). This format is implementable on other platforms.
4. The service authenticates a separate bearer access token. The passphrase never leaves the client. Knowledge of the access token permits reading/replacing ciphertext but does not decrypt it.
5. `GET /v1/sync` returns `{revision, payload}`. Empty vaults return revision 0 and null payload. `PUT /v1/sync` requires the last known revision and the encrypted envelope; a SQLite transaction increments the revision atomically or returns HTTP 409.
6. The client decrypts and validates a remote snapshot before applying it. It refuses automatic overwrite when both local and remote settings changed. A remote copy identical to local state can reconcile a previous upload whose response was lost.

Sync is whole-vault optimistic concurrency, not field-level merging. The initial service has one vault and access token per deployment. Devices use that shared token; user registration, individual device revocation, teams, and multiple tenant vaults are future work. Changing the passphrase alone cannot decrypt the existing vault: coordinated vault migration/rotation is not implemented.

HTTPS is mandatory except loopback development. HTTP redirects are rejected to avoid forwarding credentials. The client detects decreasing revisions relative to a previous successful sync; there is no server-independent freshness proof for a new device. The server can observe envelope size, revisions, and access timing. End-to-end encryption does not hide that metadata or stop a server administrator from deleting data.

## Extension path

Add catalog entries only alongside a protocol adapter, capability definitions, and request/response/cancellation fixtures. Do not assume a changed model ID makes ASR protocols compatible. Keep live microphone and recorded-file capture lifecycles separate when adding adapters, preserving current HTTP behavior. Future clients must reproduce encryption test vectors and sync revision behavior before being released.

## October 2026 expansion

SharedSettings v5 adds WritingStyle records, the selected style and application bundle-ID routing; schema v1–v4 migrate in memory before validation. DeviceSettings gains DesktopOptions with safe defaults for older files. Captured settings/style/credentials remain fixed for an inference run. Recent context is a non-encoded snapshot field and a bounded, expiring in-memory buffer; it never enters the encrypted vault. Vocabulary counts merge by stable ID after background matching.

WritingClient adapts the existing structured writing/learning prompt into Chat Completions, Anthropic Messages or Responses. SSE framing preserves empty event delimiters and split UTF-8; provider parsers require a successful terminal state. Partial output is presentation-only. Existing focus/selection/insertion receipt checks still guard all external replacement, including style-only selection edits.

Audio remains 16 kHz mono PCM. Qwen HTTP and Google inline limits are handled with local sample-preserving chunks chosen near quiet boundaries. LiveAudioFeed archives PCM only when retention is opted in. Private WAV files are referenced by generated UUIDs in local HistoryEntry records; deletion and retention operate only on those local references. Historical retries use a fresh settings snapshot and never auto-paste into a stale destination.

The optional update client is separate from inference and encrypted sync. It trusts a configured Ed25519 key, requires HTTPS, validates SHA-256 and ZIP paths/size, checks bundle metadata and code signature, and stages replacement outside the running bundle. No third-party package was introduced: CVoiceDraft is a small wrapper around macOS system zlib for bounded gzip decoding. See [updates.md](updates.md).
