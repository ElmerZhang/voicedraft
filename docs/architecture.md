# Architecture

Current feature expansion and migration details: [selected-features.md](selected-features.md). The original sections below document the initial Qwen architecture; where they describe v4/four-minute/500-entry limits, the v5 rules in the expansion take precedence.

## Boundaries

```text
SwiftUI views
    -> AppState (recording workflow, settings, synchronization)
        -> AppKit / AVFoundation (shortcuts, audio, focus, insertion)
        -> LocalStore / KeychainStore (local persistence)
        -> VoiceDraftCore
            -> SpeechClient / WritingClient -> HTTPTransport / WebSocket session -> configured provider
            -> SyncCrypto -> SyncClient -> encrypted configuration server
```

Views submit changes through AppState; they do not write storage. The model adapter owns provider protocol details; the coordinator owns capture, cancellation, output delivery, and history. The server stores opaque encrypted configuration and does not proxy inference, receive audio, or manage model billing.

Completed recognition without text is represented by `SpeechRecognitionError.noSpeech`. AppState quietly releases capture/tasks/effects, closes the HUD and returns to ready without writing empty history or invoking the writing model. Silent chunks are skipped within longer Qwen recordings; only an entirely empty combined transcript is no-speech. Malformed responses, transport failures, incomplete hypotheses and empty writing output remain failures.

Onboarding has four steps: optional field selection/starter vocabulary, models, permissions, and shortcut guidance. It keeps its heading and navigation outside a scrollable step body and reuses model controls without the full Models page heading. While mounted, its cancellable task refreshes microphone and Accessibility status every 500 ms, including while System Settings is frontmost. `VOICEDRAFT_CAPTURE_ONBOARDING=<directory>` renders all four steps with isolated preview data, AI/software selections and synthetic granted permissions, then exits; this does not test a real OS permission change.

`DomainVocabularySelection` owns the curated AI, software, product/design, data, hardware, and education/research packs. Domains are multi-select and optional; each term can be unchecked. Explicit exclusions survive domain deselection/reselection within the sheet. Continue adds only reviewed terms as ordinary enabled manual entries (strength 50, no priority) through AppState's existing save/sync flow. Existing terms, aliases and preferred spellings, including disabled entries, are matched case/width-insensitively and never overwritten or re-enabled. Global vocabulary/learning preferences remain unchanged. No profession profile or schema change is needed; selection drafts are local to the sheet. Set up later does not import a draft. Existing users can reopen the guide from Settings. The catalog deliberately avoids generic PR/UI/API/AI/README entries. Canonical naming references include [FigJam](https://www.figma.com/figjam/), [LangChain](https://reference.langchain.com/) and [Raspberry Pi](https://www.raspberrypi.com/products/raspberry-pi-pico/); bundled packs are editable vocabulary suggestions, not an accuracy guarantee.

The sync server is a separate Go module in `server/`: `cmd/voicedraft-sync` owns environment configuration and graceful process shutdown; `internal/syncserver` owns HTTP validation/authentication and SQLite transactions. It uses Go's `net/http` and `database/sql` with a pinned [pure-Go SQLite driver](https://pkg.go.dev/modernc.org/sqlite), producing a binary with `CGO_ENABLED=0`. There is no Python server runtime. HTTP protocol v1, envelope fields, environment variables, and the existing `vault` table are unchanged. An immediate SQLite transaction protects revision comparison and replacement across independent connections/processes. See [server.md](server.md) for in-place migration and deployment.

Synthetic provider endpoints live in `internal/testfixture`, linked only by `cmd/integration-test`; the production command does not expose or include them. Go service tests use `httptest.ResponseRecorder` and actual temporary SQLite databases, so validation/storage coverage does not require listening on a port. The separate integration command starts a loopback server for the existing Swift client tests.

## Desktop navigation and editing

The main shell has Home, History, and Vocabulary navigation; these are the only main pages. Home's first row shows enabled dictate/translate/edit/ask/insert-last bindings as single-line informational key-cap rows on the left and a usage summary on the right (four Total-usage tiles, one Yesterday line hidden when yesterday is empty, and a footnote; Personalization only in Settings → Usage), stacking in that order only when a column would be narrower than 340pt. The former recording/text-testing workspace is no longer mounted on Home. Recording remains available through global shortcuts and the menu bar; model, device and permission controls remain in Settings. The window uses a full-size content view with a hidden title so the sidebar reaches the top edge. Carbon receives press/release events; an explicitly configured Fn key, alone or in a chord, uses an Accessibility event tap (see Fn shortcuts below). The pure RecordingGesture state machine distinguishes hold-to-talk from tap-to-lock, including microphone startup.

`UsageActivity` in VoiceDraftCore projects AppState's retained history into exactly 365 local calendar days ending today, with empty padding to complete weeks using the system calendar's first weekday. Each saved history entry counts once (including text-only, retry and retained failure entries); this is not a count of successful insertions or model calls. Settings → Usage shows this activity calendar and the five voice metrics below for the same 365-day window; saved entries and active days remain a secondary caption. Home uses `UsageSummary` for all retained history through today (not just the calendar window), with the same five voice metrics. Yesterday uses the previous local calendar day and is omitted when its count is zero, including first-use and empty-history states. Both projections refresh every minute; Home’s View more opens the Usage settings tab through `AppState.openSettings("Usage")`. Day cells expose the date, count and recorded minutes through hover details, tooltips and accessibility labels. Density levels are 0, 1–3, 4–7, 8–15 and 16+ entries. Calendar arithmetic handles DST and leap days, and the visible window refreshes every minute. Deleting/expiring history updates the projection; history opt-out pauses new entries. The UI explicitly describes this retained-history scope and has empty/off states. No new storage, telemetry, inference, sync payload or model-usage-log read is introduced.

### Voice usage metrics

Home's yesterday/total groups and the Usage tab share `UsageMetrics`: dictation time, dictated words, weighted average WPM, estimated time saved, and Personalization. These are local projections of retained history, not provider token counts or a lifetime ledger. Only entries with positive finite duration and a nonempty letter/number transcript contribute. Count `original`, never generated `result`, so Ask answers, translated output and text-only tests cannot inflate speech metrics. History retry currently creates another entry carrying the original duration; it counts again, as explained in Usage's calculation disclosure. No existing history is rewritten and no new persisted fields or requests are added.

- Tokenization normalizes case and width. Han and Japanese kana count one unit per character; other scripts use letter/number runs, retaining internal apostrophes. Punctuation and emoji do not count. Mixed-language WPM therefore means these word/character units per minute, not a benchmark comparable across languages.
- Speed is total units / total dictation minutes (duration-weighted, never an average of take speeds). With no eligible recording, speed and Personalization display a dash.
- Estimated savings = max(0, units / 45 × 60 − dictation seconds). The 45-unit/minute typing baseline is an explicit product assumption, informed by the keyboard comparison on [Typeless's public homepage](https://www.typeless.com/); this does not reproduce or claim their private statistics formula. Processing, correction and delivery latency are not measured or deducted. UI labels and the disclosure mark this as an estimate.
- Personalization is the fraction of transcript units covered by complete token-sequence matches against the currently enabled personal vocabulary, including term, output spelling and aliases. A trie enforces whole-word matching and complete phrases, preserving symbols so C++ does not match plain C; overlapping matches count each transcript unit once. Both manual and automatically learned enabled terms participate. Globally disabled vocabulary produces 0% for nonempty speech. This is current vocabulary coverage, not recognition accuracy, proven model adaptation or observed user correction. Editing vocabulary recomputes prior coverage; the UI explicitly explains that scope.
- Calendar hover state lives in its own view subtree, so pointer movement does not retokenize history or rebuild the vocabulary trie. No-match/zero-use cells remain accessible and the local-day window continues refreshing every minute.

Settings is an in-window modal with its own navigation for general settings, Personalization, Models, Usage, Sync, About, and Help. The sidebar footer and Command-comma open the same modal through `AppState.openSettings(tab)`, which sets `AppState.settingsTab` and `AppState.page = "Settings"`. Models and Sync are settings tabs, not pages; a legacy `page` value of `Models` or `Sync` is normalized to the overlay on that tab. While it is open, the underlying page is disabled, preserving the existing pause on periodic configuration sync while forms are edited. Closing (including Escape) restores the previous main page. Models and Sync retain their existing editors and coordinator calls.

Vocabulary searches terms and aliases, filters All / Auto-added / Manually-added, and has an independent enabled/disabled filter. Automatic terms use a teal sparkle; manual terms use a leaf. Add/edit, bulk add, enable, and delete actions update a fresh copy of shared settings through `AppState.save`. Entries retain their stable IDs, origin, and all rich vocabulary fields. Successful edits save immediately; validation/persistence errors keep the editor open. Writing style and translation target have an explicit Save action in Personalization.

### Agent context vocabulary discovery

Vocabulary's context action launches a cancellable utility task through AppState. It discovers `~/.codex/AGENTS.md`, `history.jsonl`, `sessions/`, `archived_sessions/`, and Markdown under `memories/`; for Claude it reads `~/.claude/CLAUDE.md`, `history.jsonl`, project session JSONL and project `memory/` Markdown. It then checks exact `AGENTS.md`, `CLAUDE.md` and `.claude/CLAUDE.md` files in up to 12 project directories referenced by session metadata/history. It never traverses other workspace contents or parent directories. Symlinks, subagent directories, skills, hidden descendants and unrelated files such as authentication/configuration are excluded.

Referenced existing project directories also contribute their basename, including lowercase/hyphenated names, and literal names from the exact allowlist `package.json` (`name`, dropping an npm scope), `Package.swift` (`Package(name:)`), `Cargo.toml` (`[package].name`), `pyproject.toml` (`[project].name`) and `go.mod` (module basename, dropping a version suffix). Manifests are read as data, never executed; each must fit within 32 KB and the project's shared 128 KB budget. Missing, unsupported/dynamic or malformed declarations produce no name. Home directories, symlinks, generic scaffold names and invalid name shapes are skipped. There is no repository or parent traversal. Project names are deduplicated with other terms, retain both agent sources when available, and take precedence before the 200-candidate cap. A `kind: project` label gives the model supporting evidence without sending the path or manifest. The prompt still filters generic labels; review rows show `Project · Codex / Claude` as applicable.

Discovery is on demand and local. Per agent, traversal stops at 12,000 entries and depth 5; reads prioritize global context, up to 12 recent memory files, then recent conversations, with at most 80 files / 8 MB. Individual reads are at most 512 KB; oversized JSONL preserves complete header and tail lines to retain metadata and recent messages. Referenced projects have an additional 128 KB read budget each. Limits and unreadable files are reported quietly in the candidate sheet. Missing agent directories are normal.

Conversation parsing understands Codex and Claude history/session formats, deduplicates user messages within each file, and excludes assistant/tool output, tool-result wrappers, sidechains, known injected environment/instruction messages and Codex subagent sessions. Credential/URL lines are filtered before deterministic name extraction; this is a heuristic, so the user reviews candidates. Local extraction proposes at most 200 case/width-deduplicated new terms with Codex/Claude source labels, excluding current terms, aliases and preferred spellings. The selected writing model receives only candidate IDs, words and term/project labels, with no raw conversations, file paths or manifest content. Its classification prompt excludes common abbreviations, ordinary technology words, generic file labels and incidental code symbols while keeping distinctive names and specialized terms useful to speech recognition. A strict JSON parser accepts at most 40 unique, in-range IDs, preserving the original spelling/source and the model’s usefulness order. Empty selections are valid; invented IDs, malformed output or transport errors do not silently expose the unfiltered list. The sheet offers retry or an explicit unfiltered review after failure. The bounded request uses the selected Chat Completions, Anthropic or Responses protocol, a 45-second timeout and 64 KB response limit. This is one additional model request per nonempty extraction attempt. Only user-selected terms enter shared vocabulary through the existing save/sync flow. Dismissing the sheet cancels its worker and cannot import terms or publish stale results. Isolated UI preview mode never scans the real home directory.

### Automatic vocabulary learning

Two independent, enabled-by-default switches control learning from corrections and discovering terms in dictation. Both also respect global vocabulary disablement. Polish and Verbatim results can feed learning after output delivery. Translate, Edit and Ask do not teach terms from translations or model answers. This is a separate, cancellable request to the selected Qwen writing model, with a 20-second timeout; it never delays insertion or changes the delivered text. It may incur an additional inference request per completed dictation or settled correction. Failure is shown quietly in Vocabulary/Home and cannot fail the dictation.

A local prefilter (`VocabularyLearningPrefilter` in VoiceDraftCore) runs on the main actor before the learning task is created and drops discovery-only takes that contain nothing term-like, so plain dictations make no second model call. Corrections (`.editedDictation` samples and spoken correction markers) are never prefiltered. A plain dictation is still classified when its raw or final text has any of: a `TermExtractor` screen-context candidate (quoted terms, proper names, identifiers, acronyms, embedded Latin, Chinese name + title, repeated Han n-grams); in Han-dominant text, any Latin word of two or more letters outside the English UI and acronym stoplists (ASR often lowercases product names); a letter+digit token such as `qwen3` or `H100` (ordinals and `3pm`-style times excepted); an `NLTagger` `.nameType` personal, place or organization name; or letters mostly from scripts the heuristics do not cover (kana, hangul, Cyrillic and so on), which are always classified. Name tagging is best-effort: NaturalLanguage does not list the name-type scheme for Chinese, yet tags Chinese names on macOS 26, and older releases may differ. The gate errs toward classifying, since a false positive costs one model call while a false negative skips learning for that take. A skipped take changes no status and writes no `vocabulary.learning` usage-log line.

The learning prompt classifies distinctive names, products, projects and specialist terms. A strict JSON parser allows at most five corrections and five discoveries, bounded response/input sizes, short terms and exact source-text evidence. Explicit spoken recognition/spelling corrections and small user edits can add terms immediately; semantic rewrites, stutters, generic words, numbers, URLs and credentials are excluded by the prompt (structural guards also reject bare numbers, URLs and unsupported punctuation). Classification is still model-dependent, not a guarantee against incorrect terms. No global text replacement is performed, and mistaken spellings are not automatically stored as aliases.

New discoveries must occur in both raw and final text and be proposed in two distinct takes during the current app session. Repeated mentions or processing the same take twice cannot promote a term. Up to 1,000 unconfirmed spellings are held only in memory; they reset at restart, learning/model configuration changes, or remote configuration replacement. Existing enabled/disabled/manual entries and their aliases/preferred spellings are deduplicated case/width-insensitively and never overwritten. Deletion records a normalized SHA-256 spelling key to suppress later relearning, including in-flight responses; manually adding a word remains possible. The suppression hashes are not a secrecy mechanism for low-entropy terms.

For external input, an optional observer starts only after paste is posted. It must observe the expected inserted value, and then watches the same focused process/window/editor for a 45-second monotonic window. Fresh observation objects use 100 ms per-message AX timeouts without changing insertion objects or the process-wide timeout. It stops on cancellation, a new take, focus change, unreadable/secure/terminal input, an empty field, edits outside the insertion anchors, or a selection outside the dictated span. After a two-second stable edit, only the before/after dictated segment is sent for classification. Surrounding document text is used in memory to validate prefix/suffix anchors, never uploaded or persisted by this feature. (The separate, opt-in On-screen context feature below has its own egress path; correction observation is unchanged.) UTF-16 offsets must align to character boundaries. The legacy Studio result editor, no longer mounted on Home, uses a separate two-second debounce. Editors without AXValue (including some rich editors) and Warp terminals cannot provide this correction feedback; their spoken corrections and ordinary dictation discovery still work. There are no keylogging hooks or focus reacquisition.

Automatic learning merges into current settings rather than the capture-time snapshot, validates and persists through AppState/LocalStore, marks configuration dirty for encrypted sync, and respects current switches and deletion suppression. Changed models, opt-outs and remote replacement invalidate in-flight requests. Only confirmed vocabulary entries/origins, switches and deletion hashes sync; raw correction observations and pending discoveries do not. Origins and learning controls require settings schema v4.

Automatically added terms stay enabled, as requested by the user, but remain weaker evidence than manual spellings. The request projection orders manual terms before automatic ones, so recognition/writing budgets and use frequency cannot crowd them out. Weighted Qwen hints cap automatic terms at 2 (including previously stored automatic priority terms); their stored strength/priority are preserved. Editing and saving a term explicitly confirms it as manual, restoring its configured strength and priority behavior. Exact automatic duplicates of an enabled manual term, preferred spelling or alias are excluded from requests without deleting stored entries. There is no per-brand rule, inferred alias, fuzzy replacement, or confirmation queue.

History groups saved entries by local calendar date, supports text search and dictation/question filters, and retains original-transcript details, copy, single-entry deletion, clear-all confirmation, and future-history opt-out. Retention follows the configured expiry in the v5 feature expansion. Home activity is derived from retained local history, not lifetime usage or estimates of time saved. No history cloud-sync or provider zero-retention claim is made.

Page copy uses the `Desktop.strings` table in the same eight language bundles as existing controls. `VOICEDRAFT_PREVIEW=1` opens an isolated interactive preview; `VOICEDRAFT_CAPTURE_PREVIEWS=<directory>` renders the three pages (`studio`, `history`, `vocabulary`) and the settings overlay on each tab (`settings`, `personalization`, `models`, `usage`, `sync`, `about`, `help`), then exits. AppKit view caching draws scroll views in a full-size content view blank, so page captures use a standard title bar. `VOICEDRAFT_PREVIEW_APPEARANCE=dark` (or `light`) forces the appearance in isolated preview mode only. `VOICEDRAFT_CAPTURE_HUD_PREVIEWS=<directory>` renders the recording HUD states with synthetic text and exits. HUD sizes come from `DictationHUDKind`; a failure without transcript text uses the `notice` kind, a 520×160 card with only the header, error line and footer, instead of the 520×302 `failure` card. `VOICEDRAFT_CAPTURE_SHEETS=<directory>` renders each sheet's content alone in an offscreen key window at its fixed `.vdSheet(width:)` width and fitting height, writes `sheet-<name>.png` and exits: `profile-speech`, `profile-writing` (an in-memory inactive profile so Delete shows), `vocabulary-term`, `style-editor`, `bulk-add`, the import review sheet as `review-file`, `review-agent`, `review-agent-scanning`, `review-screen-reading`, `review-screen-accessibility`, `review-screen-ocr`, `review-screen-no-text` and `review-screen-no-candidates` (via `VocabularyFileControls.ReviewFixture`, which never scans or filters), and `history-clear`, an `NSAlert` stand-in with the same message and buttons as History's Clear history confirmation dialog. The `-interfaceLanguage <code>` launch arguments select the interface language for a capture through the argument defaults domain, without changing the saved preference. Tokens and shared components for every surface are defined in [design.md](design.md). Both skip persisted configuration, Keychain reads, and global shortcut registration. `VOICEDRAFT_PREVIEW_FIXTURES=1` adds synthetic vocabulary/history data only inside preview mode. Preview edits remain in memory; do not use provider, credential, or permission actions during visual checks.

## Models and inference

`ModelProfile` has a stable UUID, role, name, full endpoint, model ID, explicit adapter and additional JSON parameters. `ModelCatalog` lists only supported ASR models; each entry specifies its adapter and vocabulary capability. Text models use the chat adapter with a model picker and a custom Qwen text deployment option. A saved profile's UUID also identifies its local Keychain credential. Speech and writing profiles can have different accounts, endpoints, regions, and models. Additional JSON cannot override messages, model, streaming mode, or authentication.

Speech adapters are separate: Qwen3-ASR-Flash uses compatible HTTP chat audio and unweighted vocabulary context; Qwen-Audio-3.0/3.1-ASR-Flash uses native HTTP `input`/`parameters` and `output.text`; Qwen-Audio-3.1-ASR-Flash-Message uses task-based WebSocket inference. All models consume the same `SharedSettings.vocabulary`; profiles never own terms, weights, or vocabulary enablement. `VocabularyEntry` stores a stable ID, term, enabled flag, normalized strength (0–100), priority, language code, preferred output spelling, spoken aliases, and optional IPA pronunciation. This is the provider-independent source; adapters project a supported subset without mutating it. The first release still implements only the listed Qwen protocols, not additional providers or pronunciation training services.

`VocabularyProjection` is shared by request builders and the read-only model preview. Weighted Qwen adapters map manual strength to 1–5; the first 50 enabled manual priority terms use 50 and subsequent priority terms use 5. Automatic terms are capped at 2. They send at most 2,000 distinct terms, enforce the provider's 15-character non-ASCII / seven-word ASCII limits, and omit whole unsupported terms. Context ASR uses a client budget of 300 terms and 6,000 UTF-8 bytes without weights. Both prioritize manual origin, then priority, strength, use count and saved order; duplicate text uses the strongest eligible occurrence within that order. Current ASR adapters retain language/alias/output/pronunciation metadata locally but do not send unsupported fields. The UI reports adapter omissions, superseded automatic terms and downgraded manual priority. Writing uses the same order for up to 300 enabled entries, spelling, aliases and origin as structured guidance. It explicitly prefers user-confirmed manual spellings for clear phonetic recognition errors and treats automatic spellings as low-confidence suggestions; uncertain matches and quoted spelling examples stay intact. There are no automatic string replacements. Global vocabulary disablement affects both recognition and writing. Temporary on-screen terms (see On-screen context) are appended after all vocabulary in each adapter's budget, at weight 1 for weighted adapters, and never displace or reorder vocabulary; global vocabulary disablement also disables them.

Qwen Message ASR additionally receives whole manual terms as a `payload.input.context` user message with `input_text`, limited to 400 Unicode scalars including separators. Unsupported/oversized terms are skipped whole. Automatic terms remain in the weighted vocabulary but are not reinforced in this unweighted domain context. On-screen terms, which are current-context evidence rather than stale guesses, take whatever room is left in the 400 scalars after all manual terms. No history or extra user text is sent by this path. The request shape and limits follow the [Message client-event API](https://help.aliyun.com/zh/model-studio/qwen-asr-message-client-events). Other ASR adapters retain their documented request shapes.

App storage allows longer terms than a provider (up to 30,000 characters per field, 50 aliases per entry, 200,000 entries), so old plain-text vocabulary and unsupported phrases survive migration. Sync rejects plaintext larger than 700,000 bytes before uploading, within the existing envelope/server limit. Additional speech JSON cannot bypass the global source through `vocabulary` or `vocabulary_id`; old remote resource references are retained for recovery, but require importing their contents into the app vocabulary.

Capture binds an explicitly selected `AVCaptureDeviceInput` for each take, limited to four minutes. Selection is a local device UID; nil resolves the system default at start, while an unavailable explicit device fails without fallback. The elapsed time (with a lock icon when locked) appears under the compact HUD waveform; the actual device name and elapsed time appear in its tooltip. This never changes macOS Sound settings. Session errors/disconnects fail the take; per-run identities prevent stale callbacks from changing another run.

HTTP adapters retain the recorded-file path: `AVCaptureAudioFileOutput` produces mono 16 kHz 16-bit PCM WAV, with startup/finalization deadlines, user-only file permissions, and format validation before reading and uploading after stop. The recorded-WAV Message session remains available to core callers and tests.

The Message adapter's microphone path is live. Since 2026-10-16 the microphone opens at the shortcut (t0), in parallel with the socket handshake, instead of after `task-started` (the old order lost the first word). A separate `LiveAudioRecorder` starts `AVCaptureAudioDataOutput`, configured to convert to mono 16 kHz signed 16-bit little-endian PCM. `PCM16Audio` validates the delivered sample format and byte count before upload; no raw live recording file is created. Capture runs on its own serial queue. A bounded `LiveAudioFeed` assembles 3,200-byte (100 ms) frames with at most 15 seconds (150 frames, the handshake start deadline) buffered; PCM captured before `task-started` waits there and is uploaded in order once the session is ready, and a feed already closed during the handshake (a very short take) is still uploaded and followed by `finish-task`. Overflow fails explicitly, rather than omitting speech. `onReady` still runs after `task-started` (after the start frame for Doubao) but only checks that the take is current. A microphone failure fails the take and cancels the session; a session failure fails the take and cancels the recorder, even while it is still opening. Stop drains queued capture callbacks, flushes the final partial frame, closes the feed, and sends `finish-task` only after all audio sends complete.

`MessageASRSession.transcribeLive` concurrently uploads PCM and receives events. `intermediate_result_enabled` is enabled; hypotheses replace previous text by sentence ID, finalized sentences supersede hypotheses, and heartbeats are ignored. Only finalized nonempty text after `task-finished` can reach writing/insertion. An unexpected task ID, unfinished nonempty hypothesis, premature task completion, capture failure, or interrupted upload cannot return partial success. Handshake/finalization/whole-session deadlines are 15/30/300 seconds. Cancellation and all exits close the socket and unblock sends/receives; app generation checks also reject late UI updates. There is no automatic network reconnection or audio retry. Native URLSession supplies TLS and rejects redirects. Tests inject an in-memory socket; provider availability, hardware capture and latency still require real-account validation.

Live ASR disables `disfluency_removal_enabled` even when configured in advanced JSON, preserving spoken corrections for the writing stage. Polish and Translate instruct the writer to apply unambiguous later corrections and remove those correction instructions, without executing external actions. Verbatim remains literal. The live preview is provisional and never gets inserted on its own. Protocol references: Alibaba's [client events](https://help.aliyun.com/zh/model-studio/qwen-asr-message-client-events) and [server events](https://help.aliyun.com/zh/model-studio/qwen-asr-message-server-events).

Before opening the microphone, the coordinator validates the selected adapter/model/endpoint and vocabulary. Unknown legacy ASR IDs remain available for editing but cannot fall back to chat HTTP. Provider failures expose the HTTP status, recognized diagnostic codes, and UUID request/task IDs; arbitrary error messages are omitted because providers can echo audio, prompts, or credentials.

Writing mode determines the system instruction; transcript and selected text are structured data in the user message. Qwen may still make semantic mistakes; outputs are editable and the original transcript remains accessible.

Polish and Translate share explicit dictation cleanup rules with source-language examples: remove clear stutters (including repeated characters inside a word), hesitation fillers, accidental duplicates, and abandoned phrase starts. Preserve natural reduplication, deliberate emphasis, quoted verbatim speech, negation, uncertainty, conditions, numbers, identifiers, and technical terms; ambiguous repetitions remain unchanged. Translation applies cleanup before translating into the configured target language. Tone preservation refers to intended wording, not speech disfluencies. Habitual discourse fillers such as “然后” are removed when they merely bridge thoughts, including sentence-initial use; actual event/step sequencing, logical meaning, verbatim quotations and ambiguous uses remain. Language preservation applies to retained content and does not override filler cleanup. Paired cleanup/retention examples guide this contextual decision; there is no word blacklist. No local repetition regex, extra inference pass, or model parameter override is used. The cleanup policy does not apply to Verbatim, Edit, or Ask. Request-contract tests verify mode scope and intact structured input; actual model compliance needs separate quality evaluation.

Polish separately requires language preservation at word/phrase/clause level, including ordinary words and conjunctions in mixed-language text, rather than merely retaining names or the majority language. Only minimal same-language cleanup/spelling/grammar changes are allowed; explicit self-corrections retain the dictated replacement wording. Style, application, recent-context and on-screen-context hints cannot choose a different output language, and vocabulary is not a translation glossary for already-correct expressions. Mixed-language examples and a final comparison instruction reinforce this constraint. Translation workflow instructions are present only in Translate; Edit still follows explicit editing instructions. Raw structured input remains untouched across all writing protocols. These are model instructions, not a deterministic detector or a guarantee of compliance; no language-ratio heuristic or automatic replacement is applied to returned text.

Polish output also follows the common Chinese prose conventions in the [Chinese Copywriting Guidelines](https://github.com/sparanoid/chinese-copywriting-guidelines/blob/master/README.zh-Hans.md), often called [Pangu spacing](https://github.com/vinta/pangu.js): one ASCII space at Chinese/Latin and Chinese/Arabic-number boundaries; number/unit spacing with attached percent/degree symbols; full-width Chinese punctuation without adjacent spaces; half-width digits and punctuation inside English sentences/names. Official brand spelling and internal URL/email/path/version/identifier/command/code/link-destination/verbatim-quote content take precedence. Paragraphs and the original language mix remain intact, and Japanese/Korean text is not treated as Chinese solely because it contains Han characters. This community typography policy applies only to Polish, including history rewrites through the same request builder; other modes and raw transcripts are unchanged. It is included in the existing model request, with no extra model call, new dependency, or local regex postprocessing. Protocol tests verify delivery and scope, not actual model compliance.

HTTP recordings are written to a randomly named file with user-only permissions, read at stop, then deleted even if a later model request fails. No audio is stored by the sync server. Provider-side handling follows the user's Bailian account and endpoint policies; client-side deletion is not a claim about provider retention. A forced process termination can leave a temporary recording; startup cleanup is tracked in the roadmap.

An active run captures its selected models, credentials, vocabulary, mode, selection, and input target before recording. Configuration changes do not alter a running request. Cancel invalidates the run ID and cancels the task; late responses cannot insert text. When writing fails after ASR succeeds, the raw transcript is preserved and no partial rewrite is automatically inserted.

## System integration

Input capability is classified as writable, known non-writable, or opaque, under the rule **paste unless there is evidence the focus is not an input** (modelled on TypeFlux/Typeless; per-app allowlists proved endless). This replaced the earlier invariant that an opaque focus needs positive evidence of an input (an actual focused control, a standard nonmodal window and an enabled native Paste command). Disabled and password fields are non-writable. A focused role in the reviewable denylist `TextInputCapabilities.nonInputRoles` (buttons, check boxes, radio buttons and groups, pop-up and menu buttons, menus, menu bars and their items, sliders, incrementors, progress/busy/level/value/relevance indicators, disclosure triangles, color wells, scroll bars, splitters, handles, grow areas, static text, links, images, headings, toolbars, tab groups, Dock items, rulers and ruler markers, help tags and mattes) is non-writable. Text roles (`AXTextField`, `AXTextArea`, `AXComboBox`, `AXSearchField`) with a settable value, selected text or selection range are writable; text roles without one are opaque. Every other role, including `AXWindow`, `AXGroup`, `AXWebArea`, `AXUnknown`, `AXLayoutArea`, `AXScrollArea`, `AXSplitGroup`, `AXList`, `AXOutline`, `AXTable`, `AXCell`, `AXRow`, `AXBrowser`, `AXSheet`, `AXDrawer`, `AXDocument` and unknown custom roles, is opaque. `KeyboardSurfacePolicy.acceptsOpaque` pastes into an opaque focus whenever the app has a focused window; with no focused element at all the focused window itself is the target (element nil, window set), for every app. No focused window, a known non-input role, a disabled control or a password field is not editable and gets the copy card. There is no standard-window, modal, Paste-menu or selection requirement; the former 0.5-second menu traversal at take start is gone. Opaque targets are insertion-only: their `InputTarget.selection` is empty and `value` is nil, so screen text is never retained, Edit selection reports that text must be selected, and style application is refused exactly as when nothing is selected; the collapsed range is kept and may drift like a terminal's. They are keyboard surfaces (a 300 ms clipboard grace, no AX observation) protected by the per-take `OpaqueInputFocusGuard` described below. Opaque delivery reports only paste sent, keeps the result card up as a copy fallback (see the HUD paragraph), and does not learn corrections from unreadable text. Residual risk, accepted deliberately: Command-V may reach something that is not an input (a canvas app, a Finder window, a page with no field focused) and then does nothing or inserts an object; the result card is the safety net. Probes with `VOICEDRAFT_PROBE_INPUT` on 2026-10-16 motivated the change: Herdr UI (`so.pen.herdr-gpui`, a GPUI app) exposes only its standard, nonmodal `AXWindow` as the focused element, with no children and a disabled Edit › Paste item, so the old rule refused it; iTerm2 exposes a writable `AXTextArea` and was already writable.

Focused target resolution follows explicit nested AX focus and searches bounded container descendants only for an actually focused node; it never promotes an unfocused editor merely because it exposes a caret. Known non-input controls, disabled controls and password fields stop descent. Existing paragraph-to-editor ancestor resolution then canonicalizes the target. Cycles, a 32-node budget and a 0.5-second search deadline bound traversal; AX objects use 100 ms per-message timeouts (an in-progress call can extend the deadline). The original recording target remains binding through delivery; dictation does not follow a newly focused field.

Clipboard preparation reads all item formats on one dedicated serial worker, with a 250 ms timeout and an 8 MiB retained-data limit. Failure or concurrent clipboard changes abort before any paste. A blocked provider cannot accumulate queued reads/workers; its late result is discarded. The size cap is checked after each provider returns data, so it does not bound the provider's own allocation. Focus/selection and the clipboard generation are rechecked after asynchronous preparation. A delivery lease lasts through cancellation cleanup and restoration. The lease also outlives the take's return to idle: it is held by the background receipt window and released only after the clipboard is restored. A new delivery waits up to 2 seconds (50 ms polls, cancellable) for the lease before it reads the clipboard snapshot, so it never snapshots VoiceDraft's own temporary text as the user's clipboard; if the lease is still held after 2 seconds it fails with Could not send the paste shortcut. Temporary text carries the standard transient pasteboard marker; clipboard managers may choose whether to honor it. Restoration never overwrites a newer user copy. Tests use private named pasteboards and synthetic blocked readers, not the user's clipboard or messages.

WeChat 4.1.15 on the validated Mac exposes its main window and standard window controls but no chat input element. It no longer has a dedicated rule: its window-only or container focus is ordinary opaque input under the rule above, and the normal AX editor path takes precedence whenever an editor is exposed. The existing process/window/element and selection checks still run before paste. Since opaque focus has no field identity, a per-take `OpaqueInputFocusGuard` invalidates on global clicks, ordinary key presses or any application activation during the take; configured recording shortcuts are excluded. It stores no typed characters/positions and unregisters after delivery, cancellation or failure. Opaque delivery reports paste sent without claiming AX confirmation, does not observe correction text, and never sends Enter. It cannot prove the chat recipient or input caret from AX; application-internal changes with no observed input may remain invisible. Native automation also observed this limitation in [WeChat 4.1.x](https://github.com/huj28-creator/wechat-fastbridge/issues/1).

**Fn shortcuts and chords.** A binding with key code 63 is Fn, alone (`modifiers == 0`) or combined with any of Shift, Control, Option and Command (Fn-Shift is key code 63 with modifier bit 1). Normal keys still need Control, Option or Command, and enabled bindings must use distinct key and modifier sets. The storage format is unchanged, so existing device files need no migration. Fn with a letter or other key is not supported: macOS reserves many Globe-letter shortcuts (🌐 E, C, N, D, A, M, H, Q, F and others), and detecting them would require tapping every key press system-wide. The event tap is created only when an enabled Fn binding exists and observes `flagsChanged` only, never key presses. Each observation's Fn flag and four modifier bits go to the pure `FnChordTracker` in VoiceDraftCore, which returns press, release and retarget events (`FnChordTracker.Event.Kind`: `down`, `up`, `retarget(from:)`):

- Activation needs Fn held, no active chord, and the tracker armed. It selects the enabled Fn binding whose modifiers equal the held set exactly, at Fn's press or when a modifier is added while Fn is held and nothing is active yet. Holding Shift, then pressing Fn selects Fn-Shift directly. A held set with no exact binding (Fn-Shift-Command with only Fn-Shift bound) does nothing.
- While Fn stays held, a modifier press edge (the held set grew to a strict superset of the previous one) that completes another enabled Fn binding exactly promotes the running take to it. With Fn bound to Dictate and Fn-Shift to Translate, pressing Fn starts Dictate and adding Shift retargets the same take to Translate. A retarget is neither a release nor a press. The promoting press is accepted at any time while Fn is held, not only within a short arbitration window.
- Modifier releases while Fn stays held never emit anything. People release chord keys in arbitrary order, so letting go of Shift a moment before Fn keeps Translate and never demotes the take to Dictate. A held set that matches no enabled Fn binding keeps the current action, so unmatched intermediate chords (Fn-Control on the way to Fn-Control-Shift) and extra modifiers never end or cancel a take.
- Only Fn's release sends the release, for whichever action is current.
- This follows the promotion model observed in TypeFlux's open-source hotkey arbiter (start on Fn, promote when the chord completes in either key order); no code was copied. Unlike TypeFlux, any chord key's release other than Fn does not end the take, and promotion has no time limit.
- A new activation needs Fn released and pressed again. If the active binding stops being bound while Fn is held, it is released and the tracker stays disarmed until Fn is let go.
- `GlobalShortcuts` forwards retargets through `onRetarget` and moves its pressed state from the old action to the new one, so the later release is matched and deduplicated. `AppState.retargetShortcut(from:to:)` acts only when `from` is the held key. The held key always moves to `to`, so Fn's release finishes the take even when the switch is refused or `to` does not record. The take's mode changes only while it is starting or recording and `TakeRetargetPolicy` allows it: the action must record (`ShortcutAction.recordingMode`), a writing key must exist, and Edit selection needs the selection captured when the take started. A refused switch keeps the current mode and sets the same status message a take start would show. A retarget keeps the take: audio, screen context reading (its record only updates the mode used by the HUD term count), HUD and `generation` all continue, and delivery uses the final mode. An accepted retarget restarts the gesture's tap-versus-hold window (`RecordingGesture.retarget(at:)`) at the chord, so Fn, Shift, then a quick release of Fn locks the Translate take exactly like a Shift-Fn tap, while holding the chord and speaking still finishes on release. A tap-locked take has no held key, so it never retargets. The compact HUD shows the current mode's icon for non-Polish modes.
- The tap consumes only Fn's own edges (key code 63). Other modifier edges pass through so applications keep a consistent modifier picture. A tap disabled by timeout or user input is re-enabled.

`TextInsertion.capture(ignoring:)` passes the bindings to `OpaqueInputFocusGuard`, whose global monitor ignores key presses that match an enabled binding. Fn and its chords produce only `flagsChanged` events, which that monitor does not observe, so they never invalidate opaque focus and need no special case.

Fn's event tap consumes both press and release, but macOS's separate Globe action can still switch input sources or invoke emoji/Dictation. Fn users must set **System Settings → Keyboard → Press Fn (Globe) key to → Do Nothing** ([Apple keyboard settings](https://support.apple.com/en-gb/guide/mac-help/kbdm162/mac)). Home, shortcut preferences and the final onboarding step show `FnShortcutStatus` for enabled Fn bindings. The view reads `com.apple.HIToolbox/AppleFnUsageType` through `FnSystemAction`; only explicit zero is ready, with missing/unknown values requiring a settings check. A cancellable one-second refresh runs only while the view is mounted with an enabled Fn binding, including while System Settings is frontmost. Preview mode skips OS reads. The settings button opens the native Keyboard pane; VoiceDraft does not write the preference or claim it can restore its live behavior on quit. This system-wide choice persists outside VoiceDraft. Other shortcut events continue through the existing Carbon/event-tap paths.

SwiftUI owns the application menu through scene commands; AppKit owns the main window and recording panel. Standard editing shortcuts (undo, redo, cut, copy, paste, and select all) dispatch through AppKit's responder chain to the focused editor, including model configuration sheets. Do not assign `NSApp.mainMenu` during launch: SwiftUI can replace it when assembling its scene menus.

All single-line inputs, including custom model IDs and global vocabulary fields, use `SingleLineField`, an AppKit `NSTextField`/`NSSecureTextField` bridge with `usesSingleLineMode` enabled. The native field editor replaces pasted line/paragraph separators with spaces and suppresses newline insertion commands; text scrolls horizontally. A one-line height or SwiftUI `lineLimit` alone is not an input constraint. Keep the native editing path for undo, selection, and input methods; multiline transcript, selection, vocabulary, style, and JSON editors remain `TextEditor` views.

On explicit saves, profile names/endpoints/model IDs, translation targets, API keys, and sync URL/token values are trimmed at their edges. Model requests also trim the model ID and reject a whitespace-only ID, including for older stored configurations and unsaved connection tests. Model editors trim existing profile values on opening; search ignores outer query whitespace. Sync passphrases retain their exact spaces, since those spaces affect encryption. Existing credentials are not rewritten merely by opening a page. Model editors check Keychain metadata and display a fixed masked placeholder plus a saved-key label. The placeholder is never credential data. An empty replacement preserves the stored key; removing it requires the explicit Remove saved key action followed by Save. Cancelling leaves Keychain unchanged.

Carbon global hotkeys start/stop workflows. A nonactivating AppKit panel that cannot become key or main displays a compact Cancel/waveform/Finish capsule without stealing focus. With live text it expands upward into a scrollable preview; after a result requiring manual copying it shows a persistent, scrollable copy card. The card closes immediately after a successful Copy, on dismissal (its close button or Escape), or when replaced by another take. Automatic insertion into a writable editor or a listed terminal closes the panel as soon as Command-V has been queued. A paste into an opaque target instead leaves the result card up (`AppState.presentQueuedPaste`), headed and with the status Paste sent · copy here if nothing appeared, so the user can copy if the paste went nowhere (the Typeless behaviour); it closes the same ways. A shortcut press that arrives while the previous take is still processing (writing; the insertion receipt window no longer keeps the workflow busy) is ignored by the gesture, but it re-shows the compact Processing capsule and sets the status Still finishing the previous take…, so the shortcut does not look dead; the capsule hides again when delivery ends. A failed clipboard write keeps the card and its text available. Accessibility captures the frontmost application's focused element and selected range/text. Writable text inputs qualify directly; opaque focus, or no focused element, qualifies whenever a focused window exists. A writable selection range also qualifies a web editor for Command-V even when its text attributes are read-only. Focused text/paragraph children resolve to the nearest input ancestor, with cycle/depth limits. Disabled and password inputs stop ancestor traversal and remain excluded.

Before insertion, the app rechecks editability, process, window, canonical field, selection, and range. Empty editor values allow a missing caret to become the zero caret; unknown/nonempty values do not get this exception. Replacing an editor's focused paragraph does not change its destination, while moving to another field still does. Errors distinguish app/window/input/selection changes. No focused window, a known non-input or protected focus, disabled automatic insertion, Ask mode, or failed focus validation routes the completed result to the copy card; a missing focused element alone no longer does when a focused window exists. Missing Accessibility authorization and insertion errors are shown on the copy card instead of silently looking like absent input focus. Home also surfaces missing Accessibility authorization; a rebuilt ad-hoc signed app may need to be reauthorized by the user.

Insertion temporarily supplies the clipboard and sends Command-V with a private event source. It does not write AXSelectedText: Chromium can acknowledge that setter while its web accessibility action dispatcher ignores the requested replacement. An acknowledged AX write or a posted keyboard event is not insertion confirmation. Insertion is split in two; this replaced the earlier invariant that the receipt window keeps the workflow busy. `TextInsertion.send` returns as soon as Command-V is queued, and the workflow goes idle immediately. Receipt observation and clipboard restoration continue in an unstructured main-actor task under the delivery lease, sized by `InsertionReceiptPolicy`: 20 polls of 75 ms with the Accessibility check for text fields, or a single 300 ms clipboard grace with no AX observation on keyboard surfaces. When that task ends, Home's status is updated with the outcome unless a newer run or a cancel has replaced the take. For text fields the app polls the original field for up to 1.5 seconds, comparing its value with the expected UTF-16 selection replacement; editors omitting AXValue can confirm with the exact changed caret offset. Identical replacements require the expected selection collapse. Only confirmed updates report Text inserted. A sent paste without an exact AX receipt is a separate outcome, not a thrown insertion failure. For a writable editor its already-hidden HUD stays hidden without a success checkmark or Copy prompt, and Home reports Paste sent · check the input field. For an opaque target the result card shown after the paste keeps its status Paste sent · copy here if nothing appeared (`applyDeliveryOutcome` leaves it in place). This avoids offering a duplicate paste when a rich editor has accepted text without exposing a matching AX value/range. The result stays available in Home and, when enabled, History; there is no automatic retry. Missing input or pre-send failures still show the copy card. Existing clipboard formats are restored on confirmation or timeout only if no newer clipboard change occurred. Once paste is queued, cancellation does not remove the temporary clipboard before this bounded observation finishes. The app never sends Enter or runs a model-generated command. Selected-text access and insertion require real-app compatibility testing.

**Insert last result again.** The `insertLast` shortcut (default Control-Option-V) and the menu bar item Insert last result re-deliver `AppState.result`, the last output of a recording or Studio's text path, to whichever input is focused now. This recovers a take that was pasted into the wrong app, where clipboard restoration means Command-V would paste the old clipboard. It reuses the normal pipeline: `TextInsertion.capture` (with the per-take opaque focus guard), then `TextInsertion.send` with clipboard preservation, receipt observation and the same confirmed / paste sent to terminal / paste sent without confirmation outcomes. The shortcut acts on its release, never on press, and is ignored while a run or update is busy; it never starts a recording. Control or Option can still be physically held after the key is released, so before capturing the target it polls `CGEventSource.flagsState(.combinedSessionState)` for up to one second until Shift, Control, Option and Command are all up. If they are still held, nothing is pasted. The menu item waits 0.25 seconds for the status menu to close; the status menu does not activate VoiceDraft, so the previously frontmost app is captured. The action holds the workflow busy (`phase` processing) only until Command-V is queued; Escape cancels it through the normal cleanup before that point. The delivery lease, not the busy phase, protects the temporary clipboard during the receipt window, so pressing the shortcut within about 1.5 seconds of a paste waits for that lease before reading the clipboard. After a paste into an opaque target the result card stays up with the status Paste sent · copy here if nothing appeared, as for a take. Missing Accessibility, no editable target, held modifiers, or an insertion error shows the result copy card with the reason and the status Result ready · open VoiceDraft to copy. An empty result shows the compact notice card. A re-insert is not a new take: it writes no History entry and does not touch recent-input context, vocabulary learning or correction observation.

Escape cancels active input during microphone startup, recording, and processing through the same cleanup path as the Cancel button. Independent AppKit local and global key-down monitors cover VoiceDraft and the frontmost destination app, including when no Fn shortcut is configured or shortcut registration fails. Background key monitoring requires Accessibility authorization. `AppState.handleEscape(hudVisible:)` decides: an active input run is cancelled; otherwise, when the app is idle and the HUD panel is shown, a result, failure or notice card is closed through `dismissHUD()`, the same path as its close button. Either case consumes VoiceDraft's own local Escape. With no run and no visible card, Escape keeps native behavior. An updater installation (`busy` while `phase` is idle) is never cancelled and blocks dismissal. The global monitor observes without suppressing the destination app's Escape, so closing a card from another app also delivers Escape to that app. Cancellation clears held-shortcut state so releasing Fn afterward cannot finish the cancelled take. Monitors are removed at app termination.

`TextInsertion.send` returns a `TextInsertionDelivery` right after posting both paste events. Its `outcome` task is created inside `send`, never as a child of the caller, so cancelling the take cannot shorten the clipboard window; it restores the clipboard and releases the lease on every path, including an early confirmation. After `send` returns, AppState hides the current run's HUD (or, for an opaque target, shows the result card through `presentQueuedPaste`), starts correction observation when enabled, sets the run idle and starts vocabulary learning, then applies the final status when `outcome` resolves, guarded by the run generation. Status stays at Inserting text… until then. Failures before posting throw from `send`, release the lease, restore the clipboard if it was already written, start no background task, and still present the copy card. `cancel()` never touches the clipboard or the background task; the bounded window finishes on its own.

Warp (`dev.warp.Warp-Stable`) and Ghostty (`com.mitchellh.ghostty`), listed in `KeyboardSurfacePolicy.terminalBundleIdentifiers`, have a terminal keyboard-surface path for their standard, nonmodal window when focus exposes an enabled neutral container, a text area without a writable value, or no AX element. Under paste unless proven otherwise this allowlist is no longer needed for insertion to happen (their surfaces are opaque and would be pasted into anyway); it is kept because it yields the more precise Paste sent to terminal outcome without the opaque fallback card. Ghostty exposes its terminal surface as an `AXTextArea` whose value is the whole screen text (tens of thousands of characters) with no settable value or selection range, and its menu bar exposes no Paste command to AX; the `VOICEDRAFT_PROBE_INPUT` probe confirmed this on 2026-10-16. Ghostty's own clipboard paste protection may still ask before a multi-line paste; VoiceDraft never answers that dialog. Exposed disabled/secure controls, buttons, normal form fields and dialogs do not use it. The same process, window and exposed surface must remain focused; only collapsed selection offsets may drift as terminal output advances. Terminal output is not treated as a replaceable editor value or insertion receipt, and the target's `value` is left nil so the screen text is never retained. After one Command-V and the 300 ms clipboard grace period (`InsertionReceiptPolicy`), this path reports Paste sent to terminal rather than Text inserted. The result remains in Home and, when enabled, History. This is best-effort keyboard delivery: AX cannot establish pane identity when no focus element exists, or prove that a TTY application accepted/echoed the paste. Other apps retain editor confirmation. Real Warp/Ghostty/TUI compatibility and pane switching remain acceptance checks.

**Electron accessibility.** Electron apps such as Slack Desktop do not build their accessibility tree until an assistive client announces itself, so the focused composer is missing and dictation fell back to the copy card. Electron's documented application attribute for third-party assistive technology is `AXManualAccessibility`. During `TextInsertion.capture`, when the frontmost application element reports that attribute as settable and no writable editor is focused (focus missing or not `.writable`), VoiceDraft sets it to true once per process (`ElectronAccessibilityPolicy.shouldEnable` in VoiceDraftCore). Native apps and Chrome report the attribute as unsupported, so they are never touched. After the first enable the capture polls for a focused element for at most 0.3 seconds in 50 ms steps on the main thread, then continues with the normal resolver; the terminal, opaque and secure-field paths are unchanged. A cold Slack tree was measured at about 2.2 seconds. Since opaque focus is now editable, pending means "this process was just enabled and the resolved focus is not a writable editor" (`ElectronAccessibilityPolicy.capturePending`; a listed terminal surface is never pending), so a cold Slack window still waits for its composer instead of receiving the opaque fallback paste. Before automatic insertion of an external take (auto-paste on, not Ask), and before Insert last result, a pending target is re-captured every 0.25 seconds until it becomes a writable editor, the frontmost process changes, or 2.5 seconds after the enable have passed; a later take gets one immediate re-capture. Only a same-process writable result replaces the original target, and its fresh value and range feed the insertion receipt; otherwise the original target is used: an opaque fallback paste with the result card, or the copy card when it is not editable. Every insertion check, including the password-field rule, still runs. Enabled processes are tracked by PID and launch date and pruned when they exit. On quit VoiceDraft sets the attribute back to false in those still running, best effort, unless VoiceOver is on. Electron does not report the stored value (reads return 0), so the quit reset cannot be verified by reading it back. `AXEnhancedUserInterface` is deliberately not used: Slack returns not implemented, and it causes window-animation side effects in other apps.

### On-screen context

Opt-in and off by default (Settings → General → On-screen context). When the user dictates into another app, VoiceDraft reads the text visible in that app's front window and uses it three ways: lowest-priority recognition hints, a bounded writing reference for Polish/Translate (terms only for Edit), and on-demand "Extract words from this screen" into the Vocabulary review sheet.

**Boundary.** This is the first feature that uploads text VoiceDraft did not produce and the user did not select: surrounding window text goes to the user's configured speech and writing providers. It is a separate, explicit egress path; correction observation still never uploads surrounding document text. Speech models receive only term-shaped tokens (2–64 characters, ≤ 4 words, no newline). The writing model receives at most 1,500 redacted characters plus ≤ 40 terms as `on_screen_context_reference_only`, with a system rule that it is untrusted reference data that may only resolve names, terms, spellings and tone. That rule is a model instruction, not a guarantee. No code parses instructions, paths or URLs from screen text, the app never executes model output, and insertion keeps every focus check. Ask and Verbatim receive nothing. Screen data travels only as explicit request parameters; it is never stored on `SharedSettings`, in History or in sync. The only disk copy is the opt-in diagnostics file below, which holds screen-derived terms (never the excerpt) and exists only while its hidden switch is on.

**Mechanics.** Pure algorithms live in VoiceDraftCore (`ScreenContext.swift`, `TermExtraction.swift`); the app target supplies adapters.

**Budgets.** AX walk: 4,000 nodes, depth 40, walk deadline 1.2 s (`axWalkSeconds`; extraction allows 1.5 s), partial results every 0.1 s, 2,000 characters per node, 20,000 total. ASR gate 250 ms (`asrGateSeconds`). OCR 2 s from take start. ASR ≤ 300 terms / 6,000 UTF-8 bytes. Excerpt ≤ 1,500 characters; writing terms ≤ 40, high-confidence only. Cache 60 s, 4 entries shared by AX and OCR snapshots. Extraction ≤ 200 candidates.

The old 12-level depth cap was the cause of thin results in Electron apps: Slack's message text sits deeper than 12 levels, so the walk saw only 61 nodes and the window title. AX messages answered in about 0.04 ms each in Slack, so the node and time budgets were not the limit (see validation.md, 2026-10-15).

**Walk deadline versus gate.** The ASR gate and the walk deadline are separate. The live gate waits at most 250 ms and then uses whatever is ready: the complete walk if it finished, otherwise the latest partial collection merged with this window's cached complete snapshot (≤ 60 s old), plus fresh or cached OCR. The walk keeps going to its 1.2 s deadline. The complete result feeds the writing reference and is cached under the window key, so the next take in the same window starts from it. A partial collection with enough content (≥ 120 characters) also settles the OCR decision early. Partial walks are never cached.

**Chat names.** Chat transcripts carry the names users dictate most often, and NLTokenizer splits unknown Chinese names into single characters. `TermExtractor.chatNames` therefore adds high-confidence proper names from:

- Sender labels: a line-initial name followed by ":" or "："; a name line followed by a time ("10:32", "上午 10:35", "Today at 9:41:15 AM") on the same line or within three lines with only short separators between; or a name that repeats as a whole line. Han labels are 2–4 characters (longer only with a title suffix) and cannot start with a pronoun or function character. Latin labels need a time, or a colon plus repetition or two title-case words, or two title-case words repeated. Field labels (时间, 备注, Note, Subject…) and UI words are rejected.
- Name + title or kinship suffix: 1–2 Han characters + 老师/同学/先生/女士/爸爸/妈妈 (小易老师, 程老师, 高琪爸爸), or a common surname + 总/哥/姐 (王总). The name starts on an NLTokenizer word boundary, so 谢谢程老师 yields 程老师; 总是, 哥们, 各位老师 and similar words are rejected.
- `ScreenTermExtractor` also runs the sender rules over body and control segments interleaved in reading order, because Slack exposes each sender as a button followed by its permalink and time.

```text
     ├─ AX walk (screen-context queue, ≤ 1.2 s + message overrun)
     │     ├─ window key at once → cached complete AX snapshot for this window, if any
     │     ├─ partial collection every 0.1 s (enough text → OCR not needed)
     │     ├─ complete collection → writing snapshot + AX cache
     │     └─ needs OCR && OCR on && permitted → window lookup → capture → Vision (deadline t0 + 2 s) → cache
     ├─ live adapters (Message WS, Doubao): microphone opens at t0 (PCM queues in the feed, ≤ 15 s)
     │     while the socket handshake starts, then
     │     await asrTerms(until: t0 + 250 ms) = complete walk if done, else partial + cached AX,
     │     plus OCR or cached OCR for the window, else []
     │     → start frame → task-started → queued PCM drains in order (order changed 2026-10-16:
     │       the gate delays only the start frame, never capture)
     └─ HTTP adapters: recorder starts immediately; at stop currentASRTerms() never waits
deliverTranscript: writingContext() waits only until t0 + 2 s (normally already past)
end of take: end(take:) cancels work (the walk stops at its next node), writes the
             diagnostics line when enabled, and drops the record; late results are discarded
```

OCR never delays ASR start. If the walk is slow, live ASR proceeds with the partial walk and cached snapshots (or nothing); the complete walk still feeds writing. The first take in an OCR-only app has no ASR screen terms, only the writing reference.

**Adapter injection.**

| Adapter | Screen terms go to | Effective cap |
| --- | --- | --- |
| Qwen3-ASR chat | projection context after vocabulary | leftover of 300 terms / 6,000 B |
| Qwen Audio HTTP | weighted vocabulary at weight 1 (15-scalar / 7-word rule) | leftover of 2,000 |
| Qwen Message WS | weighted vocabulary at weight 1, plus `input.context` after all manual terms | leftover of 400 scalars |
| Doubao | hotwords after vocabulary | leftover of 100 |
| Whisper | prompt after vocabulary, cut at a whole term | leftover of 1,800 characters |
| Google | phrase set after vocabulary | leftover of 100 |

**Never persisted, counted or learned.** Usage counting only increments stored entries. Discovery learning receives the keys of every screen term offered to speech or writing for the take and cannot promote them; correction learning from explicit user edits is unaffected. Extraction imports only terms the user checks.

**Permissions.** Accessibility is already required. Screen capture has two separate macOS gates:

1. TCC Screen Recording, which `CGPreflightScreenCaptureAccess()` reports and `CGRequestScreenCaptureAccess()` requests.
2. From macOS 15, a ScreenCaptureKit approval kept by replayd ("bypass the private window picker"), asked again about monthly. Preflight stays true while this alert is due. The alert appears at the first actual capture (`SCScreenshotManager`), not at an `SCShareableContent` query.

The user-reported prompt during the first take was gate 2. TCC was granted, preflight was true, and the take performed the session's first capture (validation.md, 2026-10-15).

`ScreenRecordingPermission.request()` runs from the OCR switch (turning it on), the Settings Allow button, Home and onboarding:

- When preflight is true, it immediately performs the confirmation capture described below, so a due approval alert appears now.
- Otherwise it calls `CGRequestScreenCaptureAccess()`, which shows the TCC prompt when the permission is undetermined.
- If no system prompt took focus within 0.8 s and preflight is still false, it runs one `SCShareableContent` query (macOS 14+, result ignored), which asks for an undetermined permission.
- Only a repeated request that raised no prompt opens Privacy & Security.
- It then polls preflight for 60 s and confirms once it turns true. Preflight can stay false until relaunch after a grant.

The confirmation capture is a 2×2-pixel capture of the main display, discarded at once; four averaged pixels hold no readable content. A session that completes it is "capture-confirmed" (memory only, nothing on disk). Automatic triggers try once per session: launch with OCR on, and the Settings page while OCR is on. A declined alert is therefore not repeated; the switch and Allow buttons may retry.

Takes and extraction only check `capturePermitted`: preflight true and, on macOS 14+, capture-confirmed. Nothing in a take requests, queries or captures before that check passes. A take can still meet the monthly re-approval if the app has run for weeks since the last confirmation; when it is declined, OCR is skipped quietly.

**Extraction.** The status menu item waits 0.25 s for the menu to close, reads the still-frontmost app, then opens Vocabulary's review sheet in screen mode. Vocabulary's button reads the last tracked external app; the app need not be frontmost for AX. Exclusions always apply; OCR runs only when its switch is on and permission is granted. Only candidate IDs, words and kinds reach the writing model.

**Input focus probe (diagnostic launch mode).** Launching the app with `VOICEDRAFT_PROBE_INPUT=<bundle identifier>` runs `InputFocusProbe` at the top of `applicationDidFinishLaunching` and exits before `AppState`, windows, the status item, global hotkeys, screen-context observation or the updater exist, so it reads and writes no settings, history, usage or Keychain data. It uses VoiceDraft's own Accessibility grant, which a plain shell lacks. It prints `key=value` lines: `AXIsProcessTrusted` (exit 2 when false), the target app (exit 1 when not running), then for the raw focused element and up to 8 ancestors the role, subrole, value type and length, selected-text length and range, settability of value, selected text and selected range, enabled, focused, and the attribute, parameterized-attribute and action names; for the focused window its subrole, modal flag and title length. It then traces `TextInsertion.classify`, the code path `capture` runs for the frontmost app: `resolveFocus`, the Electron retry, focused and editor capabilities, window flags, the terminal keyboard-surface and opaque policies, each nil-returning guard and the resulting `editable`, `keyboardSurface` and `opaqueApplication`. With a trace, failed guards are reported instead of returning nil, and the frontmost check normally fails because the target need not be frontmost. The probe never prints text content, only lengths, counts and names. Production calls pass no trace and keep the original guard behaviour.

**Diagnostics (opt-in).** A hidden device-local switch, the `ScreenContextDiagnostics` Bool in `UserDefaults`, has no UI:

```sh
defaults write com.voicedraft.mac ScreenContextDiagnostics -bool true    # on
defaults delete com.voicedraft.mac ScreenContextDiagnostics              # off
```

While it is on, `ScreenContextDiagnosticsLog` appends one JSON line per take (at `end(take:)`) and per extraction to `~/Library/Application Support/VoiceDraft/Diagnostics/screen-context.jsonl`. The file follows the usage log's rules: shared `JSONLines` writer, folder 0700, file 0600, silent failures, never synced, read or shown, and nothing in preview mode.

Fields:

- `v`, `kind` (`take` or `extraction`), `date`, `takeID`, `bundleID`, `sources`
- `nodesVisited`, `charactersCollected`, `axElapsedMs`, `ocrElapsedMs`, `truncated`
- `gateHadTerms` (live adapters only), `asrTermsSent`
- `termsOffered` (every term offered to speech or writing, or the extraction candidates)
- `excerptLength`, `writingTerms`

**The file contains screen-derived words** (terms and names read from other apps' windows). It never contains the excerpt or any other screen text. It exists only because the switch was turned on; turning the switch off stops writing, and deleting the `Diagnostics` folder removes it.

**Preview.** Isolated preview mode never reads AX, captures a window or requests permissions; extraction returns an empty scan. `VOICEDRAFT_CAPTURE_PREVIEWS` also writes `settings-screen-context.png` (the section rendered alone, since it sits below the fold), and `VOICEDRAFT_CAPTURE_HUD_PREVIEWS` adds `screen-context` and `screen-context-compact`.

## Persistence

`~/Library/Application Support/VoiceDraft/` contains versioned settings, per-device preferences, and up to 500 history records in user-readable JSON with mode 0600. The directory uses mode 0700. This is local storage, not an encrypted history database. Keys and the synchronization access token/passphrase use Keychain items accessible only on the device while unlocked.

History, recordings, microphone settings, paste preferences, and server login details are not part of the shared configuration. Disabling history affects future entries; deletion removes existing entries separately. Before an explicit remote replacement, the previous nonsecret settings are copied to `settings-before-sync.json`. This backup excludes keys; it is not a full encrypted vault backup.

### Model usage log

Every inference call appends one JSON line to `~/Library/Application Support/VoiceDraft/Usage/usage-YYYY-MM.jsonl` (month of the call's start in the local time zone; folder 0700, files 0600). It exists to evaluate cost later. It is always on, device-local and append-only. It is never synced (`SharedSettings` is untouched), never read or shown by the UI, and independent of the History switch, history retention pruning and **Clear history**. Preview mode writes nothing. To clear it, delete the `Usage` folder. Write failures are silent and never interrupt a take.

Covered calls: live and recorded speech recognition, History **Transcribe again**, writing for dictation and Studio, vocabulary learning, agent-context vocabulary filtering, and the profile editor's **Test connection**. Model discovery (`/models`) is not inference and is not logged. Dictations skipped by the local vocabulary-learning prefilter make no learning call, so monthly `vocabulary.learning` totals count classified takes only. `AppState.metered` wraps each call; core clients report provider usage through an optional `@Sendable (ProviderUsage) -> Void` sink and know nothing about the file.

Record schema `v: 1` (`ModelUsageRecord`):

| Field | Meaning |
| --- | --- |
| `v`, `id`, `date` | Schema version, record UUID, call start (ISO 8601) |
| `kind` | `speech`, `writing`, `vocabularyFilter`, `learning` or `connectionTest` |
| `source` | Exact call site (`ModelUsageSource`, stable raw values; see below) |
| `adapter`, `model`, `profileID`, `profileName` | `ModelAdapter` raw value, model ID and profile identity |
| `host` | Endpoint host only; never the path, query or credentials |
| `mode` | `WritingMode` raw value for writing and connection tests |
| `streamed` | Streaming writing request or live speech socket |
| `audioSeconds` | Recording duration for speech calls (live: final take duration; History retry: stored duration) |
| `latencyMs` | Wall time from call start to result or error |
| `outcome`, `failure` | `ok` or `failed`; failure is only `http:<status>`, `timeout`, `cancelled`, `network` or `other` |
| `takeID` | Run generation shared by a take's speech, writing and learning calls |
| `usage`, `usageAvailable` | `ProviderUsage` when the provider reported counts; failed calls usually have none |

`source` values. Raw values are a log contract: add cases, never rename them.

| Source | Call site |
| --- | --- |
| `dictation.liveSpeech` | Live WebSocket recognition during recording (Qwen Message, Doubao) |
| `dictation.speech` | HTTP recognition after the recording stops |
| `dictation.writing` | Writing pass of a dictation take |
| `studio.writing` | Studio **Process** on the editor text |
| `history.transcribeAgain` | History **Transcribe again** recognition of the retained recording |
| `history.rewrite` | Writing pass of History **Rewrite transcript**, and of **Transcribe again** after its recognition (both share one path) |
| `style.applyToSelection` | Applying a writing style to selected text in another app |
| `vocabulary.learning` | Correction learning and dictation discovery |
| `vocabulary.agentContextFilter` | Model filtering of agent-context (Codex/Claude) candidates |
| `vocabulary.screenContextFilter` | Model filtering of **Extract words from this screen** candidates |
| `models.connectionTest` | Profile editor **Test connection** |

`ProviderUsage` normalizes `inputTokens`, `outputTokens`, `totalTokens` (input + output when not reported), `cachedInputTokens`, `audioTokens` and `reportedAudioSeconds`, and keeps every numeric field of the provider's usage object in `raw` with dot keys (for example `prompt_tokens_details.audio_tokens`, `cache_creation_input_tokens`), bounded to 64 fields. Anthropic `input_tokens` excludes cache reads/writes; see `raw`. A chunked long Qwen HTTP recording sums its chunks. Never written: transcript, result, selection, prompt, screen or vocabulary text, provider error messages, credentials, or full URLs.

| Adapter | Usage source |
| --- | --- |
| Chat Completions, Qwen chat writing | Non-streaming `usage`; streaming adds `"stream_options": {"include_usage": true}` and reads the final usage chunk |
| Anthropic | `message_start.message.usage` merged with cumulative `message_delta.usage`; non-streaming `usage` |
| Responses | `response.completed` → `response.usage`; non-streaming `usage` |
| Qwen chat speech (Qwen3-ASR-Flash), Qwen Audio HTTP | Top-level `usage` (tokens, audio details, `seconds` when present) |
| Whisper-compatible | `usage` when present (`type: duration, seconds` or token counts) |
| Qwen Message WebSocket | `task-finished` `payload.usage` when sent (for example `duration`) |
| Doubao, Google Speech | None; only `audioSeconds` and latency |

Streaming Chat Completions requests get `stream_options` unless the profile's additional JSON defines `stream_options` (then it is sent unchanged). If the service answers HTTP 400 and the error body mentions `stream_options`, the request is retried once without it and logged with `usageAvailable: false`. After the finish event the client waits up to five seconds for the usage chunk, `[DONE]` or EOF; a finished response is kept when the connection then closes. Non-2xx streaming responses now go through `ProviderFailure` like non-streaming ones, so the HTTP status and recognized provider codes are shown and logged.

## Device shortcut migration

Shortcut bindings live in per-device `device.json` (`DesktopOptions.shortcuts`), not in the synced `SharedSettings` payload, so the sync protocol and encryption envelope are unaffected. Builds before `insertLast` decode the `shortcuts` array strictly (an unknown action makes the whole device file fail to load) and accept at most five bindings. Newer builds therefore write the five original actions under `shortcuts` and newer actions under a separate `additionalShortcuts` key, which older builds ignore. On decode, both arrays are merged, entries with unknown action names are skipped, and `ShortcutBinding.fillingDefaults` appends any missing action with its default binding, disabled when an enabled binding already uses the same keys. An older build that saves the device file drops `additionalShortcuts`; the next newer launch re-adds the default.

On-screen context settings (`screenContext`, `screenContextASR`, `screenContextWriting`, `screenContextOCR`, `screenContextExcludedApps`) decode leniently and are sanitized at decode, so a malformed value never makes the device file unreadable. Older builds ignore these keys; if an older build saves the device file, they are dropped and the feature returns to off on the next newer launch, which is the privacy-safe direction.

## Settings schema v4

Schema v4 adds vocabulary origins, learning switches and deleted-term suppression; v3 terms default to manual with IDs and metadata unchanged. v3 introduced one rich app vocabulary and removed per-profile speech vocabulary settings. v1 protocol migration still infers only exact catalog IDs and repairs known paths on the existing origin; custom paths and unknown IDs stay editable. v1/v2 vocabulary migration starts with global lines, merges terms from all speech profiles, and lets the active profile win conflicting overrides. Its default weight maps to the global strength scale, its vocabulary switch becomes the app switch, and disabled inactive-profile terms remain disabled. Stable IDs derive from namespaced term hashes so decoding the same legacy snapshot twice preserves equality for sync conflict detection. Legacy tab separators normalize to spaces; long valid legacy terms are retained. Profile UUIDs, key associations, and unrelated model parameters remain intact. Migration does not access credentials or persist automatically; the next settings save (including an automatically learned word) writes v4. Older clients reject v4, so update every syncing client before sharing it. The encryption envelope and opaque server protocol are unchanged.

## Interface localization

Eight resource catalogs cover Simplified Chinese, Traditional Chinese, English, Japanese, Korean, German, French, and Spanish. `LocalizedMessage` separates stable source keys from interpolated user values; `L10n` resolves an explicit choice or the ordered system languages, with English fallback. Language is a local UserDefaults preference, separate from the translation target and encrypted shared settings. Switching it refreshes view labels, existing status messages, menu commands and menu-bar entries without rebuilding editor state. Cocoa-owned dialogs use the app-only `AppleLanguages` preference on the next launch; main-bundle `InfoPlist.strings` localizes the microphone usage description. User text, history contents, names, model IDs, parameters, and model prompts are never translated when changing the interface.

SwiftPM bundles must be copied into `Contents/Resources`; packaged builds explicitly resolve that copy and do not silently depend on the development build directory. Chinese lproj names are matched case-insensitively because SwiftPM lowercases them. `scripts/check-localizations.py` checks all catalog keys, argument placeholders, microphone descriptions and source literal coverage; Swift tests verify language matching and actual translated lookup for all eight languages.

## Encrypted sync protocol v1

Plaintext snapshot: `{settings: SharedSettings, credentials: {profileUUID: apiKey}}`.

1. The client validates the snapshot and derives a 256-bit key from the passphrase using PBKDF2-HMAC-SHA256, 600,000 iterations, and a fresh random 16-byte salt for each upload.
2. AES-256-GCM encrypts the UTF-8 JSON with a fresh nonce. Authenticated associated data is the UTF-8 string `VoiceDraft.sync.v1`.
3. The envelope has exactly `version: 1`, `algorithm: "PBKDF2-SHA256+AES-256-GCM"`, `iterations: 600000`, `salt` (base64), and `ciphertext` (base64 of CryptoKit's combined `nonce || ciphertext || tag`). This format is implementable on other platforms.
4. The service authenticates a separate bearer access token. The passphrase never leaves the client. Knowledge of the access token permits reading/replacing ciphertext but does not decrypt it.
5. `GET /v1/sync` returns `{revision, payload}`. Empty vaults return revision 0 and null payload. `PUT /v1/sync` requires the last known revision and the encrypted envelope; a SQLite transaction increments the revision atomically or returns HTTP 409.
6. The client decrypts and validates a remote snapshot before applying it. It refuses automatic overwrite when both local and remote settings changed. A remote copy identical to local state can reconcile a previous upload whose response was lost.

Sync is whole-vault optimistic concurrency, not field-level merging. The initial service has one vault and access token per deployment. Devices use that shared token; user registration, individual device revocation, teams, and multiple tenant vaults are future work. Changing the passphrase alone cannot decrypt the existing vault: coordinated vault migration/rotation is not implemented.

HTTPS is mandatory except loopback development. HTTP redirects are rejected to avoid forwarding credentials. The client detects decreasing revisions relative to a previous successful sync; there is no server-independent freshness proof for a new device. The server can observe envelope size, revisions, and access timing. End-to-end encryption does not hide that metadata or stop a server administrator from deleting data.

## Extension path

Add catalog entries only alongside a protocol adapter, capability definitions, and request/response/cancellation fixtures. Do not assume a changed model ID makes ASR protocols compatible. Keep live microphone and recorded-file capture lifecycles separate when adding adapters, preserving current HTTP behavior. Future clients must reproduce encryption test vectors and sync revision behavior before being released.

## October 2026 expansion

SharedSettings v5 adds WritingStyle records, the selected style and application bundle-ID routing; schema v1–v4 migrate in memory before validation. DeviceSettings gains DesktopOptions with safe defaults for older files. Captured settings/style/credentials remain fixed for an inference run. Recent context is a non-encoded snapshot field and a bounded, expiring in-memory buffer; it never enters the encrypted vault. Vocabulary counts merge by stable ID after background matching.

WritingClient adapts the existing structured writing/learning prompt into Chat Completions, Anthropic Messages or Responses. SSE framing preserves empty event delimiters and split UTF-8; provider parsers require a successful terminal state. Partial output is presentation-only. Existing focus/selection/insertion receipt checks still guard all external replacement, including style-only selection edits.

Audio remains 16 kHz mono PCM. Qwen HTTP and Google inline limits are handled with local sample-preserving chunks chosen near quiet boundaries. LiveAudioFeed archives PCM only when retention is opted in. Private WAV files are referenced by generated UUIDs in local HistoryEntry records; deletion and retention operate only on those local references. Historical retries use a fresh settings snapshot and never auto-paste into a stale destination.

The optional update client is separate from inference and encrypted sync. It trusts a configured Ed25519 key, requires HTTPS, validates SHA-256 and ZIP paths/size, checks bundle metadata and code signature, and stages replacement outside the running bundle. No third-party package was introduced: CVoiceDraft is a small wrapper around macOS system zlib for bounded gzip decoding. See [updates.md](updates.md).
